## 0. 关键背景（决定全部结论）

- **租户开关**：`MybatisPlusConfig.tenantEnable`，默认 `false`（`aigicrm.tenant.enable:false`），仅 `TENANT_ENABLE=true` 时开启。
- **租户白名单（25 张业务表）**：`biz_approval*`、`biz_contact`、`biz_customer*`、`biz_customer_log/share/transfer`、`biz_file*`、`biz_folder_acl`、`biz_incentive_category/permission/record`、`biz_invoice`、`biz_payment`、`biz_reminder`、`biz_score_*`、`biz_sea_*`。
- **核心事实**：`JdbcTemplate` 原生 SQL **一律绕过** MyBatis-Plus 租户拦截器。凡是命中白名单表的原生 SQL 且不带 `tenant_id` 条件，开租户后即跨租户泄漏。
- 本次扫描共命中：jdbc 调用 **~40 处**；`@PreAuthorize` **173 处**；无注解映射方法 **12 个（多数为鉴权/自检/已在方法内守卫）**；catch 吞异常默认返回 **18 处**；小程序 `.catch()` **118 处**。

## 7. 给修复方的优先级建议
1. **#1 改密撤销 fail-open** 与已知 `isBlacklisted` 同根：Redis 故障时鉴权/撤销判定应 fail-closed（拒认）或落库兜底，而不是「不失效」。建议改 `isInvalidatedByPasswordChange` 在 Redis 异常时回查 DB `pwd_changed_at`（代码注释已提到该 DB 兜底存在，但此路径未接上）。
2. **#2 getDuplicateInfo** 原生 SQL 补 `tenant_id` 条件，或改回 MyBatis-Plus 走拦截器。
3. **#3 激励写/删接口** 补 `@PreAuthorize` 作为第二道防线。
