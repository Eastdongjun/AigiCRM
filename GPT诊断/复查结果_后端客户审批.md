## E21 客户排行原生 SQL 与范围缺口（SQL 全文逐行核对）

- **诊断声明要点**：`CustomerService.java:750-817` 三段 SQL 全文，确认表名、JOIN、WHERE、GROUP BY、ORDER BY 与摘录一致，且无 tenant_id/group_id 条件。
- **源码实际定位**：`CustomerService.java:758-818`
- **核对结果**：逐字一致
  - **SQL1 customerIncentiveRanking（759-773）**：
    - SELECT：c.id AS customerId, c.customer_name, owner.real_name AS ownerName, c.industry, `COALESCE(SUM(ir.score),0) AS totalScore`, `COUNT(ir.id) AS uploadCount`, 四个 file_*_id 非空 CASE 计数（preCount/midCount/postCount/trackCount）。
    - FROM `biz_incentive_record ir` JOIN `biz_customer c` ON `c.id = ir.customer_id AND c.deleted = 0` LEFT JOIN `sys_user owner` ON `owner.id = c.owner_id`。
    - WHERE `COALESCE(ir.score, 0) > 0`；GROUP BY `c.id, c.customer_name, owner.real_name, c.industry`；ORDER BY `totalScore DESC, uploadCount DESC, customerName ASC`。
  - **SQL2 customerRelationshipRanking（778-786）**：
    - FROM `biz_customer c` JOIN `biz_customer_indicator i` ON `i.customer_id = c.id` LEFT JOIN `sys_user owner`。
    - WHERE `c.deleted = 0 AND COALESCE(i.relationship_score, 0) > 0`；ORDER BY `relationshipScore DESC, customerName ASC`。
  - **SQL3 customerCoreIndicatorRanking（791-816）**：
    - SELECT 含 relationship_score、indicator_02~05、`COALESCE(inv.invoiceAmount,0)`、`COALESCE(pay.paymentAmount,0)`、totalScore 合计、coreCustomer CASE（`invoiceAmount>=100 AND paymentAmount>=100 AND totalScore>=12 THEN 1 ELSE 0`）。
    - FROM `biz_customer c` JOIN `biz_customer_indicator i` LEFT JOIN `sys_user owner` LEFT JOIN (SELECT customer_id, SUM(amount) AS invoiceAmount FROM `biz_invoice` WHERE deleted=0 GROUP BY customer_id) inv LEFT JOIN (SELECT customer_id, SUM(payment_amount) AS paymentAmount FROM `biz_payment` WHERE deleted=0 GROUP BY customer_id) pay。
    - WHERE `c.deleted = 0 AND (relationship_score + indicator_02+03+04+05) > 0`；ORDER BY `totalScore DESC, coreCustomer DESC, customerName ASC`。
  - 三段 SQL 均无 `tenant_id`、`group_id`、`owner_id = 当前用户`、`dept_id` 或任何数据范围过滤；`deleted=0` 是唯一的行过滤（且仅在 SQL1 位于 JOIN 条件中）。
- **结论**：**属实**
- **备注**：诊断声明列举的四张表（biz_customer/biz_incentive_record/biz_invoice/biz_payment）为核心聚合表，SQL 实际还 JOIN 了 biz_customer_indicator 与 sys_user 用于取指标和负责人名，不影响"无范围条件"的核心结论。
