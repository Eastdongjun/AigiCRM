# 文件管理权限体系 — 交付报告

> 2026-08-05 | 状态：**已部署生产并实测通过** | 设计：`docs/superpowers/specs/2026-08-05-file-permission-design.md` | 计划：`docs/superpowers/plans/2026-08-05-file-permission.md`

## 交付结果

- 文件管理从"管理员/所有者二分"升级为**按文件夹的角色授权（ACL）**：公共文件夹可授权角色上传/编辑/删除/分享/下载，私人文件夹可授权查看，直属上级可见可管理下级文件
- **下载开关**：文件夹可设"允许下载/仅预览"（防资料外传）
- **覆盖替换**：文件可替换新内容，版本号递增，保留记录与链接
- 现有分享功能保留，分享按钮按权限显示

## 使用说明（管理员）

1. 文件管理 → 公共/私人文件夹 → 行操作"权限设置" → 选择角色 + 勾选权限（查看/上传/编辑/删除/分享/下载）→ 保存
2. 同一弹窗可切换"允许下载"开关（关闭=全员仅预览，管理员不受限）
3. 文件行"替换"图标（有编辑权限）→ 选新文件覆盖，版本号 +1
4. 直属上级：用户设 `manager_id` 或部门设负责人（leader）后自动获得下级文件的管理权

## 残余风险与观察项

- **上级链真实数据**：生产 `manager_id` 全空（29/29 未维护），部门 leader 部分设置——个人上级功能需在人员管理中逐步维护后生效（部门链兜底可用）
- **偶发下载**：点击文件夹偶发触发一次文件下载（无法稳定复现，来源未明），上线观察
- 公共根目录非管理员可"新建文件夹"（前端按钮）但后端拒绝（根级公共需管理员）——UX 待后续对齐
- 上传接口接受任意 scope 字符串（列表不可见但占存储）——观察项
- 部署凭证惯例、`~/.mavenrc` 损坏（用 `MAVEN_SKIP_RC=true` 绕过）——环境遗留
