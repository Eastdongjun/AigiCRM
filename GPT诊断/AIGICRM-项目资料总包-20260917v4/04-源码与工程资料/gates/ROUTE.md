## 每次执行的路线

1. 从用户实际请求记录目标、可修改对象、验收点；审计走只读证据路线，不进入业务修复。
2. 运行本机能力自检；缺 AGENTS、ROUTE、workspace、VS Code CLI、Sonar 或蓝图/推进入口时先修工程配置，不进入业务实现。
3. 用 `blueprint_planner.py --project AIGICRM.COM` 从用户需求生成全景蓝图、验收点、变更边界和 To-Do List；未生成蓝图不得开始写代码。
4. 核对源码根、构建入口、分支、修订和已有改动。登记文件归属；路径或源码不完整时先诊断，不猜命令。
5. 只执行蓝图当前 To-Do。实现任务逐条建立“验收点 → 接口/领域不变量 → 修改范围 → 验证方法”的对应关系。架构检查覆盖依赖方向、权限、事务、幂等、兼容与失败恢复，按实际变更选用。
6. 从构建文件与现有 CI 核实命令，先读脚本及其依赖，确认是否触达生产。缺失技能不得列作可执行步骤；可用原生工具完成同等检查时记录替代入口。
7. 在已授权范围内实现或修复；失败先分类代码、环境、配置、依赖或需求原因，再处理根因。复验原失败项和相关回归，不机械重跑整套检查。
8. 质量检查分别记录测试、构建、Lint/类型、架构审查、VS Code Problems/SonarQube/SonarLint、服务端 Sonar 门禁。VS Code 本地诊断不能替代服务端门禁，服务端门禁也不能替代本地诊断。扫描错误、零扫描范围、NOT_COMPUTED、旧版本分析、必需项跳过均为未验证。
9. 每个 To-Do 交付前调用 `task_progress_engine.py`；缺原检查、相关回归、VS Code 诊断、review、handoff 或前后 baseline 证据时保持 blocked，不能进入下一 To-Do。
10. 用户要求清零时核对约定范围的全部问题，不能以“零新增”冒充“全部清零”；不得关闭规则或扩大排除范围来通过。
11. 逐条核对验收与实际证据、审查发现和处理结果。必需项不通过就不能报告可交付。发布仅在请求包含发布时执行，另外检查迁移、可观测性和回滚。
