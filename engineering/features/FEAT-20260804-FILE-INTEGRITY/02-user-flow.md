# 用户流与状态流

## 主路径

非 UI 功能,用户可见行为变化:
- 上传:用户上传激励/文件 → 写盘 → 回读校验(大小一致)→ 返回成功。校验失败 → 返回业务错误,无残留记录
- 部署:任意部署方式(compose / deploy-backend.sh)挂同一 upload-data 卷,文件跨部署可见
- 备份:每日 02:30 备份新卷全量数据,日报含"文件缺失: 0"
- 日志:容器重建后日志文件保留在挂载卷

## 异常路径

- 写盘后回读不一致:删除已写文件,接口返回"文件上传失败",用户可重试
- 巡检发现缺失:日报标记缺失文件数,判定"需要人工介入"
- 备份脚本修正后首次运行失败:NAS 容量/权限问题,保留旧脚本备份可回滚

## 状态转换

- biz_file:insert 仅在"写盘+回读校验通过"后发生(REQ-003 强化)
- 记录 57:file_pre_id 由 [159,162] 改为 [162](一次性数据修正,不可逆,已获用户确认)
- 测试文件 159/160:物理删除 + 记录删除(已获用户确认)

## 不适用说明

ui_scope=none:本功能不涉及用户界面改动(前端 3 个 vue 的 Codex 未提交修改保留不动)。
受影响接口:POST /api/file/upload(校验逻辑);nginx 响应头(对全部 HTTP 响应生效);
无页面/组件/布局变更,无需浏览器视觉验证。
