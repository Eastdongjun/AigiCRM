- 数据已两级：4 一级 + 12 二级；孤儿 46/47/48 无记录引用
- 页面入口：系统设置 → 激励类别与权限

- 类别最多两级是业务规则（现有页面已限制，后端补强制）

## 阻断问题
无

## REQ-001：一级/二级分组展示
激励类别管理区块改为按一级类别分组的清晰展示：一级类别作为分组标题/卡片，其二级子项列于其下；子项归属一目了然，不依赖树形缩进。

## REQ-002：数据整理
删除孤儿垃圾类别 46/47/48（"213/111"），删除前导出备份；删除后列表不再出现这些数据。

## REQ-003：后端强制两级
后端创建/更新类别时校验 parentId：必须为 0（一级）或现存顶级类别 id（二级）；否则拒绝并返回明确错误。防止三级嵌套。

## REQ-004：操作能力保持
分组展示下，一级可"编辑/子项/删除"，二级可"编辑/删除"；**有子项的一级禁止删除**（前后端双重校验，提示先删子项），无子项时正常确认删除。

## 功能需求
- 激励类别管理区块按一级类别分组展示（分组标题 + 二级子项列表）
- 数据整理：删除孤儿类别 46/47/48（先备份）
- 后端强制两级：创建/更新校验 parentId 必须为 0 或顶级 id

## 业务规则与权限
- 类别层级最多两级：一级（parentId=0）→ 二级（parentId=一级 id）
- 一级分值为 0，二级设置实际分值（沿用现有约定）
- 类别管理操作权限沿用现有：激励专项权限（biz_incentive_permission）控制编辑/删除
- 仅启用类别（status=1）出现在激励上传页（现有行为，不改）

## 异常与边界
- 删除带子项的一级类别：前后端双重拒绝，提示先删子项（用户已确认，非级联删除）
- 后端校验 parentId 不存在/非顶级：返回明确错误信息，不静默
- 删除孤儿类别时若存在并发新增引用：删除前复查引用数
- 类别名称为空/重复：沿用现有前端必填校验，后端不新增约束

## 非功能需求
- 前端构建通过；页面控制台 0 error
- 删除孤儿类别前导出备份（evidence/）
- 不改变激励上传/查询页行为（回归抽查）
