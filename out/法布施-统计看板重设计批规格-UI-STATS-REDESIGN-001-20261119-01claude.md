## 二、后端聚合规格（口径写死，QC 按此复算）

1. **periodReadUsers（周期已读人数）**：周期内 read_status distinct user（可见集内）。周期沿用 dashboard 现实现，不重定义。
2. **书目阅读 rollup**：read_status(post_id)→post→section(book_id)→book(title, category)；已读人数=distinct user、人次=count read、最新=max(read.created_at)；feed 帖（无 section 链）排除；只算 PUBLISHED 帖。
3. **类别已读口径**：书目 rollup 按 category 再聚合已读人次；类名取字典（10 大类）。
4. **每日一读达成率**：分母=周期内"提醒开关开启∧频率匹配当日"**人日**（复用 F4a freqMatchesToday 同一判定：daily=每天、workday=周一~五、weekend=周六日）；分子=其中当日有 ≥1 条 read_status 的人日；无设置者不入分母；日界 Asia/Shanghai；周期 7 天（week）/当月（month）。显示 xx%（分母 0 显示 —）。
5. **我的-连续天数**：distinct 阅读日集合，自今日（或今日无阅读则自昨日）逐日回溯至首个断日；跨周期/跨月不限窗口。
6. **我的-最常读类别**：全量 read（不限周期）按类别累计人次取 top1。

改动落点：`FabushiDashboardService.dashboard()` 扩字段（periodReadUsers/dailyGoalRate/bookRanking/categoryReads 替换 categoryHeat——**旧字段名保留还是替换由你定，但页面不再用发布口径**）；`FabushiStatsService.personal()` 扩 4 字段；monthly 后端预计零改动（仅前端重排，核对后如实申报）。

## 四、字典驱动红线（用户 2026-11-19 指令：「不要硬编码，法布施里面很多是调用的是数据字典的值」）

1. **类别名/码零硬编码**：十大类的中文名与 code 清单，禁止出现在前端组件、后端聚合、CSV 生成、MP 页面的任何字面量里——一律运行时按码从字典 `fabushi_category` 解析（沿用 FabushiDashboardService.categoryNames() 模式：`dictService.listDataByCode` → map(value→label)，缺行回退显示 code 本身）。
2. **字典类型码提取共享常量**：`"fabushi_category"` 字符串如出现多处，提常量（S1192 同治）。
3. **跟随性**：管理员在字典 UI 加第 11 类、改名、停用——统计自动跟随，不改代码；无数据的类不显示（自然过滤）。
4. **测试 fixture**：可用真实码造数据，但断言不得依赖中文标签（label 属字典数据，改字典不该红测试）。
5. 其他字典值同理：凡 fabushi 里走数据字典的展示值（类别为本次主项），统计侧一律字典口径，新增展示如最常读类别/书目榜类别列均按码解析。
