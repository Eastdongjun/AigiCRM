## F1 分型限额 + NEW 标记 + 木鱼音效（纯本地批，无窗口，无拍板依赖）

### F1-1 限额（图≤5 / 视≤5 / 音≤10 段且 ≤60s/段）
**后端** `FabushiPostService.addAttachment`（现仅 scope 校验+sortOrder 计数）追加：
- 常量 `MAX_IMAGE=5, MAX_VIDEO=5, MAX_AUDIO=10, MAX_AUDIO_SECONDS=60`
- 按本帖既有附件 `fileType` 分型计数，超限抛 `BusinessException(400, "图片已达上限5张"/"视频已达上限5段"/"语音已达上限10段")`
- `fileType=audio` 且 `durationSeconds != null && > 60` → 400 "单段语音不得超过60秒"；`durationSeconds=null` 暂放行（F2 录音上线后必填，本批不破坏聊天文件选音频的旧路径）
- 音单测矩阵：5/6 张图、5/6 段视、10/11 段音、60/61 秒边界

**MP** `pages/fabushi/upload/index.js`：
- `chooseMedia`（:76）现 `count: 9-attachments.length` 改为分型：返回的 `tempFiles[].fileType` 拆 image/video，分别对 5 上限截断并 toast "图片最多5张，已保留前5"
- 音频（:84）`count:1` 保持，但校验 `audCount<10` 才入口
- wxml 附件区加分型计数提示 `图片 x/5 · 视频 x/5 · 语音 x/10`

### F1-2 NEW 标记（30 天窗口）

### F1-3 木鱼音效

## F2 语音录制（本地批为主，live 用例需一窗）

**MP `upload/index.js` 新增录制面板**：
- `wx.getRecorderManager()`；`start({format:'mp3', duration:60000, sampleRate:44100, numberOfChannels:1, encodeBitRate:96000})`——mp3 三端（iOS/Android/微信 H5 播放）兼容最好；60s 自动停（`onStop` 收 `res.duration`）
- 段列表交互：每段显示时长、试听（InnerAudioContext）、删除、重录；段数上限 10（复用 F1 计数）；<1s 段丢弃
- `scope.record` 拒绝 → 引导 `wx.openSetting`；`onHide/onUnload` 录制中 → stop 并保留 ≥1s 段
- 上传链路：段 → `uploadFile(path, null, 'fabushi')` → `addAttachment({fileId, fileType:'audio', durationSeconds: Math.round(duration/1000)})`
- `chooseMessageFile` 旧入口保留为"从聊天文件选"次按钮

**语音评论（互动·语音诵读）**：`detail/index` 评论面板加录音模式（单段 ≤60s）→ `addComment({type:'audio', audioFileId, content:可选标题})`；**先核** `FabushiPostService.addComment` 是否透传 `type/audioFileId`（实体有字段，service 未接则补）

**"重点描述"互动（拍板 2026-11-19：评论的一种类型）**：评论增加 `type:'highlight'`（文字精华评论），detail 页评论列表高亮渲染（如"重点"徽标+描边样式）；可限作者/管理员可设或全员可设——实现取全员可设（最轻），渲染区分。

**live 用例**：`test-fabushi-upload-limits.js` 加 case4（第 11 段→400）、case5（61s→400）——测试服窗口，20 提前知会，QC pin 基线 A 八项。

## F3 H5 上传通道 + 短时票 + reader 换票（安全设计先行，拆 a/b 控爆炸半径）

### F3a 法布施 H5 上传 + reader 换票
**票制（后端，复用既有 JWT 机制）**：
- `JwtTokenProvider` 增 `generateTransferToken(uid, parentJti, scope, scene, ttlMin)`，`scope ∈ {download, upload}`；upload 票 TTL 5 分钟；沿用现有 `generateDownloadToken`（FileController:46 `/download-token`）签名体系，新增 scope/scene claims
- 新端点 `GET /api/fabushi/upload-ticket`（`fabushi:create`，主 JWT 走 header）→ `{ticket, expiresIn:300}`
- 新上传端点 `POST /api/file/upload/h5?ticket=…`（**无主 JWT**）：校验票 scope=upload ∧ scene=fabushi ∧ 未过期 → 走 `FileService` 同路径同闸（scene=fabushi，单文件 图≤10MB/音≤20MB/视≤100MB/PDF≤100MB）
- 发票限速：同 uid 60s ≤10 张（Redis INCR+EXPIRE）
- **红线：任何情况下主 JWT 不进 URL**（这是 QC 验收的 grep 红线）

**H5 页（aigicrm-ui，同 `/mp-file-picker` 先例）**：
- 公共路由 `/mp-fabushi-uploader` + `views/mp/FabushiUploader.vue`（纯静态无登录态）：`<input type="file" multiple accept="image/*,video/*,audio/*,.pdf">`、前端大小预检、队列 UI（进度/失败重试）、完成后 `wx.miniProgram.postMessage({fileIds})` + `navigateBack`
- URL 只带 upload 票（短时、scope 受限）

**MP 容器**：新页 `pages/fabushi/uploader`（web-view，src=apiBaseUrl+`/mp-fabushi-uploader?ticket=`）；`upload` 页加"从手机文件选择"按钮：先 `GET upload-ticket` → navigateTo 容器 → onShow 收 fileIds → 逐个 `addAttachment`（主 JWT header）

**reader 同批换票（MP-TOKEN-001 法布施侧闭环）**：
- `reader/index.js`（:40-47 现状 `token=`主 JWT）改：取 download 票（scene=fabushi-reader）→ src 带 ticket
- `FabushiReader.vue` 改用票调 PDF 拉取与进度回传（进度端鉴权细则实施时定，原则=不传主 JWT）

**验收**：票 TTL 过期 401 / scope 不符 403 / 限速 429 单测；真机 H5 上传手工验收；**QC 红线核验：全仓 grep 确认主 JWT 零 URL 出现**；limits 脚本加 H5 case。

## 补记（2026-11-19 用户指示后）：对齐文件管理三通道先例

用户确认方向：小程序上传受限（chooseMessageFile=聊天接口）应改用 H5 文件接口。经核 `pages/files`（2026-11-02 落地）的三通道设计，法布施上传入口对齐为**三通道**：

1. **从相册/拍摄**（原生 `wx.chooseMedia`，同文件管理通道②）
2. **录制语音**（原生 `getRecorderManager`，F2——刻意不走 H5 MediaRecorder：iOS web-view 兼容性不稳、后台易断）
3. **手机文件**（H5 `/mp-fabushi-uploader` web-view，F3——复制 `/mp-file-picker` 先例并升级：多选+类型白名单+短时票）

与文件管理先例的差异点（有意为之）：① 多文件（先例单文件 `files[0]`）；② accept 白名单；③ 鉴权从"URL 带主 JWT"改短时票（先例的弱点=MP-TOKEN-001，F3b 同批修）；④ nginx CSP 需为新路由放行 `res.wx.qq.com`（与 C7 同窗）。上传页 UI 相应重排：现有"图片/视频+音频"两按钮改为三通道入口，聊天选音频降级为次入口。
