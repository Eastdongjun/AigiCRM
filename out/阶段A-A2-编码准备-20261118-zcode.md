## 三、设计疑点（供 QC 参考；本轮未改任何草案/设计文档）

1. **【阻断】`.2` 草案在 MySQL 8 默认 `only_full_group_by` 下不可执行**：SELECT #9 `new_inherit`（裸 `d.object_type`/`d.folder_id` 的 CASE 不在 GROUP BY）与 #16 `legacy_ref`（CONCAT 内 CASE 不构成整表达式匹配）各报 1055（实测 8.0.46，日志 L395/L396 前序轮）。修复建议：两处 `MAX(CASE…)` 包裹（组内值恒同，语义不变；演练补丁见存档 `migrate-r2.sql` 的 diff 仅此两行）。不修则测试/生产 Flyway 必失败。
2. **【语义】`.2` 的 inherit 映射与设计 §2.2 矛盾**：实测 83 行 inherit=1 但新 FOLDER 行仅 33——旧 `object_type='FOLDER' AND folder_id IS NULL`（35 旧行→50 个展开组）迁成 SPACE 却带 inherit=1，设计写明「SPACE=0」。当前引擎 SPACE 分支不看 inherit（惰性无害），但 UI 展示与未来逻辑会误读。建议迁移 CASE 改为按**新** object_type 判定（SPACE→0）。
3. **【落法】读路径 mode 开关的调用点数**：设计 §2.8 写「check/checkFile/permsForFiles/permsForBatch 四处统一」，实际 `FolderPermissionService` 有 **8 处** FileGrantService 调用（另 4 处：fabushi canView/canDelete、canRollbackVersion、hasFileGrantDeny 快速路径+permsForBatch 夹 DENY）。建议开关收口在 `FileGrantService` 内部（decide* 入口判 mode，legacy 恒 ABSTAIN），8 处自动统一，避免逐点 if 漏改；旧表回落唯一入口是 `grantGranted()`+permsForFiles 的旧表 selectList。请 QC 确认此实现取向。
4. **【落法】对账退出码**：`reconcile-file-grants.sql` 是纯 SELECT，无法自身「有差异退出非 0」（设计 §2.4/§2.9 的措辞）。建议编码期包一层 `scripts/reconcile-file-grants.sh`（跑 SQL、判四数、非 0 退出）或固化为 CI/测试用例——二选一请拍板。
5. **【数据】「任一永久则永久」合并逻辑未被真实数据覆盖**：测试快照 62 行 expires_at 全 NULL（§1.2）；生产 87 行的 expires 分布未知。编码期必须用合成夹具（混合组：部分有值部分 NULL）覆盖该 CASE，否则迁移最微妙的语义零覆盖。
6. **【命名】`.1` 草案文件名 `…file_grant_inheritance_indexes` 与内容（全结构：列+唯一键+回填）不符**，转正时建议改名为 `…file_grant_scope_columns` 之类，避免后来者误以为只是索引。
7. **【生产前置核查】两件事在 A2 执行前需生产只读确认**（本轮按简报未碰生产）：① 生产 `biz_file_grant` 是否已有 2026-11-17 阶段二的手工行——若有，`.2` 的 NOT EXISTS 会跳过同键手工行而 reconcile 只看 legacy/dual_write → 误报 missing（保守阻断切换，需口径豁免或预清理）；② 生产旧表 `folder_type` 是否存在 blank 行——`.2` 未做 `NULLIF(TRIM(folder_type),'')` 归一，blank 会原样写入 `space_type=''`，与 §2.7「blank→NULL=任意空间」矛盾（测试快照无 blank，未触发）。
