# 法布施统计看板重设计方案（QC 出品 · 待用户拍板）

> 2026-11-19 用户验收指令：「这个看板的元素 分析的数据 需要重新设计」。
> 依据：spec v2 原文统计节 + stats.vue 现状（45e55eb3 后）+ 后端数据可得性核实。
> 边框修复批 45e55eb3 已 SCAN_DONE（FIXED-PENDING-DEPLOY），为本方案基底，不再重复处理。

## 一、spec 原文要求（存档 §五）

> 五、统计功能。如同四项激励的设置。
> 1、团队所有成员**每条阅读情况、阅读类别**等统计。
> 2、各个成员**阅读情况、阅读类别**等统计。

关键词：**每条阅读情况**（内容/书目维度）、**阅读类别**（按类别统计阅读）、团队+个人双层。

## 二、现状盘点与缺口

现看板 11 个元素（45e55eb3 后）：

| 元素 | 现口径 | 判定 |
|---|---|---|
| KPI×4 | 今日已读 / **新增内容 / 木鱼 / 评论** | 阅读指标仅占 1/4，互动味重 |
| 成员阅读榜 | 发布/获木鱼/**已读天数**/活跃度 | 有阅读列但非核心位 |
| 类别热度分布 | **发布数**（`buildCategoryHeat(periodPosts)` 代码坐实） | ≠ spec"阅读类别"口径 |
| 每日一读趋势 | 每日已读人数 | ✓ 贴 spec |
| 部门进度 | 覆盖率+4 计数 | ✓ 保留 |
| 月度报告 | 7 格+环比 | ✓ 保留（互动指标收编处） |
| 我的法布施 | 我的内容/评论/阅读/获木鱼 | 无类别分布、无连续天数 |
| **书目/内容维度** | **完全没有** | **"每条阅读情况"缺位——最大缺口** |

## 三、数据可得性（已核实，均为存量数据、无需新表）

- **书目阅读 rollup**：阅读记录挂在 post 上，post→章节→书目，按书聚合已读人数/人次 ✓
- **类别阅读口径**：书目→字典类别（10 大类），按已读人次聚合 ✓
- **连续阅读天数**：用户阅读记录按日去重连算 ✓
- **每日一读达成率**：提醒设置（频率）×实际阅读日 ✓

## 四、三方案

### 方案 A · 阅读优先重构（推荐，贴 spec 原意）

- KPI：今日已读 / 周期已读人数 / 阅读覆盖率 / 每日一读达成率
- 主区：成员阅读榜（**已读天数、已读人次列前置**，发布/获木鱼降后）+ **书目阅读榜（新）**：每本书 已读人数/已读人次/最新阅读
- 右栏：**阅读类别分布（已读人次口径，替换发布口径热度）** + 每日一读趋势（保留）
- 底部：部门进度（保留）+ 月度报告（保留；发布/木鱼/评论收编于此）
- 我的：已读天数 / **连续阅读天数 / 最常读类别** / 阅读人次
- 后端：FabushiStatsService/Dashboard 扩 4 个聚合（书目 rollup、类别已读、streak、达成率），dashboard/monthly 端点扩字段；**中批**

### 方案 B · 骨架小改（不动布局骨架）

- KPI 换 2 张：新增内容→周期已读人数、评论→每日一读达成率
- 类别热度改阅读口径（同一张卡换数据源）
- 右栏或底部加**书目阅读榜（简版）**一卡
- 其余全保留；后端 2 个聚合；**小批**

### 方案 C · 双视角 tab

- 「阅读视角」= 方案 A 全套；「互动视角」= 现看板原样
- 两套布局并存，切换查看；后端 = A 的聚合全做；**大批**

## 五、验收口径（QC）

1. 元素/数据按拍板方案逐项对账（页面元素清单 vs 规格）
2. 口径抽验：类别分布数字 = SQL 独立复算（已读人次）；书目榜数字同
3. 截图复验沿用 Chrome channel 通道；边框批 5 子项不回归
4. CSV 导出若同步扩：导出数字与页面一致性抽查
5. 现有门禁全绿：vitest / typecheck 基线持平 / API 契约 / 后端 mvn test + Sonar P0-5

## 六、拍板结果（2026-11-19 用户已定）

① **方案 A 阅读优先重构**；② **互动指标收进月度报告**；③ **CSV 导出同步扩口径**。
