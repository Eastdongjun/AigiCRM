# 权限与文件统一治理实施方案（2026-11-17）

> 状态：设计稿（待评审）。本稿只做方案与迁移设计，不含生产执行。
> 决策口径：客户名称全集团唯一；现有同名活跃客户 grandfather 保留；旧客户/旧人员备份后彻底删；6 个有发票/4 个有阶段金额的旧客户保留活跃；回收站 admin 手动清理；离职交接一级审批、继任人可跨区、按自身范围；组织移动只改当前数据、一级审批、留日志可回滚；法布施公司级 all 默认、删除权限按大区/办事处/部门/个人勾选、可跨大区；文件版本全字节保留、旧版冷存储；单文件 200MB；预览支持图片/视频/文档，CAD/压缩包/音频回退图标；所有审批一级、admin 配审批人。

---

## 一、目标与边界

### 目标
1. 权限：管理员勾选的功能码、数据范围、文件动作、法布施删除权限，下一次请求即生效；新增角色不改代码。
2. 恢复：客户/文件/人员/激励/任务/提醒删除后进统一回收站，可恢复；彻底删除前可导出备份。
3. 文件：所有模块文件统一进文件中心；法布施有独立页签，统一列表/删除/回收站/配额/ACL/版本。
4. 组织：公司→大区→办事处→部门→直接下级→个人，通用树可扩展；组织移动当前数据改派、历史不动、日志可回滚。
5. 交接：离职人员可恢复；数据/角色/权限可交接；一级审批；继任人可跨区。
6. 规模：客户几百万、人员 ≤10 万、文件 1000 万、并发 500；MySQL 主从+分区+Redis+对象存储+异步队列可支撑，暂不引入分布式库。

### 不做（本稿范围外）
- 不执行生产数据清理、组织移动、人员交接、权限变更。
- 不做 WPS 式在线文档内容编辑。
- 不做多级审批/会签（所有审批一级）。
- 不做 CAD/压缩包/音频预览（回退图标）。

## 二、客户名称唯一

### 归一化
- Unicode NFKC（全半角统一）。
- trim 首尾空格；内部连续空格折叠为一个。
- 中文括号（（）/【】/[] 等）统一为中文括号；异体字/特殊符号按字典归一化。
- 拉丁字母转小写；保留中文、数字、常用符号。
- 最大 100 个中文字符（超出拒绝）。

### 字段与索引
```sql
ALTER TABLE biz_customer
  ADD COLUMN name_norm VARCHAR(100) NULL COMMENT '归一化客户名',
  ADD COLUMN dup_exempt TINYINT NOT NULL DEFAULT 0 COMMENT '历史同名豁免：1=保留不参与唯一',
  ADD COLUMN active_name VARCHAR(100)
    GENERATED ALWAYS AS (
      CASE WHEN deleted=0 AND dup_exempt=0 THEN name_norm ELSE NULL END
    ) STORED COMMENT '活跃唯一名；deleted/豁免为 NULL',
  ADD COLUMN deleted_at DATETIME NULL,
  ADD COLUMN deleted_by BIGINT NULL,
  ADD COLUMN deleted_reason VARCHAR(255) NULL,
  ADD COLUMN delete_source VARCHAR(20) NULL COMMENT 'user/migration/system/cleanup';

ALTER TABLE biz_customer
  ADD UNIQUE KEY uk_customer_active_name (tenant_id, active_name),
  ADD KEY idx_customer_deleted (tenant_id, deleted, deleted_at),
  ADD KEY idx_customer_owner (tenant_id, owner_id, deleted),
  ADD KEY idx_customer_org (tenant_id, org_id, deleted);
```

### 祖父条款
- 现有 3 组同名活跃客户：`dup_exempt=1`，原样保留，不参与唯一索引。
- 新建客户：`dup_exempt=0`，必须唯一；重复返回 400“客户名称已存在”。
- 编辑豁免客户：不改名称可保存；改名称则要求新名称唯一，并把 `dup_exempt=0`（需业务确认后收口）。
- 已删客户：`active_name=NULL`，允许同名新客户；恢复时已有“无同名活跃客户”闸门。

### 现有重复数据处理
- 上线前跑差异报告：3 组同名活跃客户逐组列出 id/owner/created_at/业务引用。
- 因业务要求“保留不动”，先不合并；`dup_exempt=1` 豁免。后续业务决定合并时，再清豁免、改名/合并。

## 三、删除数据与回收站

### 主表软删
统一字段：`deleted, deleted_at, deleted_by, deleted_reason, delete_source`。
- `biz_customer`、`sys_user`、`biz_incentive_record`、`biz_task` 补字段。
- `biz_file` 已有 `deleted/deleted_at/deleted_by`，补 `deleted_reason/delete_source`。
- `biz_reminder`/`biz_approval` 保持状态机，不新增删除；如需删除走状态/归档。

### 统一回收站
```sql
CREATE TABLE biz_recycle_bin (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  tenant_id BIGINT NOT NULL,
  biz_type VARCHAR(20) NOT NULL COMMENT 'customer/user/file/incentive/task/reminder',
  biz_id BIGINT NOT NULL,
  snapshot_json JSON NULL COMMENT '完整快照；大对象存对象存储并记指针',
  snapshot_key VARCHAR(255) NULL,
  deleted_by BIGINT NULL,
  deleted_at DATETIME NOT NULL,
  reason VARCHAR(255) NULL,
  source VARCHAR(20) NULL,
  restored_at DATETIME NULL,
  purged_at DATETIME NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'deleted',
  UNIQUE KEY uk_recycle (tenant_id, biz_type, biz_id),
  KEY idx_recycle_type_time (tenant_id, biz_type, deleted_at),
  KEY idx_recycle_status (tenant_id, status, deleted_at)
) PARTITION BY RANGE COLUMNS(deleted_at) (...按月...);
```
- 热回收站保留 6-12 个月；更早归档到 `biz_recycle_bin_archive`。
- 文件只存元数据；字节在对象存储/NAS，彻底删除才清。
- 客户/人员快照 ≤64KB；超大放对象存储。

### 导出与清理
- admin-only；导出包：`data.xlsx`（按模块 sheet）+ `manifest.json` + `checksums.sha256` + `files/`（大文件给对象存储清单）。
- 不加密；导出包 7 天过期；下载/导出/清理全审计。
- 清理流程：筛选类型/时间/组织 → 预览数量 → 导出 → 审批（admin）→ 异步分批彻底删除（500-1000/批，短事务）。
- 不设自动 TTL；保留 `retention_days` 配置位（默认 0）。

### 旧数据
- 290 旧客户、40 旧人员：全库备份 + 表级导出 + 文件包到 NAS → 核对引用 → 彻底删。
- 6 个有发票、4 个有阶段金额的旧客户：保留活跃列表，不删；如需归档，另走档案流程。
- 40 旧人员：无活跃引用者删；有引用者保留归档；恢复时重新分配角色/组织。
- 全量备份 NAS 长期保留；建议第二份离线/异地（单点风险）。

## 四、文件统一管理

### 数据模型
```sql
-- 文件台账扩展
ALTER TABLE biz_file
  ADD COLUMN md5 VARCHAR(64) NULL,
  ADD COLUMN deleted_reason VARCHAR(255) NULL,
  ADD COLUMN delete_source VARCHAR(20) NULL;

-- 文件夹支持四种 scope
ALTER TABLE biz_file_folder
  MODIFY folder_type VARCHAR(20) NOT NULL COMMENT 'public/private/incentive/fabushi',
  ADD COLUMN inherit_acl TINYINT NOT NULL DEFAULT 1,
  ADD COLUMN inherit_from BIGINT NULL,
  ADD COLUMN path VARCHAR(1000) NULL;

-- 文件与业务对象引用
CREATE TABLE biz_file_link (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  tenant_id BIGINT NOT NULL,
  file_id BIGINT NOT NULL,
  biz_type VARCHAR(30) NOT NULL COMMENT 'incentive_record/fabushi_post/fabushi_book/...',
  biz_id BIGINT NOT NULL,
  slot VARCHAR(30) NULL,
  relation_type VARCHAR(20) NOT NULL DEFAULT 'ATTACHMENT',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_file_link (file_id, biz_type, biz_id, slot),
  KEY idx_biz (tenant_id, biz_type, biz_id)
);

-- 统一授权（收敛 biz_folder_acl + biz_folder_type_default）
CREATE TABLE biz_file_grant (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  tenant_id BIGINT NOT NULL,
  subject_type VARCHAR(10) NOT NULL COMMENT 'ROLE/POSITION/USER',
  subject_id BIGINT NOT NULL,
  object_type VARCHAR(10) NOT NULL COMMENT 'SPACE/FOLDER/FILE',
  object_id BIGINT NULL,
  action VARCHAR(30) NOT NULL COMMENT 'view/download/upload/edit/rename/replace/share/delete/restore/purge/version_read/version_rollback/acl_manage',
  effect VARCHAR(10) NOT NULL DEFAULT 'ALLOW' COMMENT 'ALLOW/DENY',
  inherit TINYINT NOT NULL DEFAULT 1,
  scope_org_id BIGINT NULL,
  scope_level VARCHAR(20) NULL,
  expire_at DATETIME NULL,
  created_by BIGINT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_grant (tenant_id, subject_type, subject_id, object_type, object_id, action),
  KEY idx_object (tenant_id, object_type, object_id, action),
  KEY idx_subject (tenant_id, subject_type, subject_id, action)
);

-- 版本扩展
ALTER TABLE biz_file_version
  ADD COLUMN md5 VARCHAR(64) NULL,
  ADD COLUMN change_reason VARCHAR(255) NULL,
  ADD COLUMN created_by BIGINT NULL;
```

### 权限动作与判定
- 动作：`view/download/upload/edit/rename/replace/share/delete/restore/purge/version_read/version_rollback/acl_manage`。
- 判定链：admin > 本人/上传者 > 直属上级链 > 文件/文件夹例外授权 > 空间默认授权 > 组织数据范围 > 拒绝；DENY 优先，继承可断。
- 数据范围：`all/region/office/dept/team/self/custom`，走统一 `OrgScopeResolver`；文件/文件夹 `org_id` 为锚点。
- 管理员按角色/人员 + 数据范围勾选；`file:delete`/`fabushi:file:delete` 带范围。

### 法布施
- 文件中心新增“法布施”页签；统一列表/删除/回收站/配额/ACL/版本。
- 权限码：`fabushi:file:view/upload/edit/delete/restore/purge/version_rollback/acl_manage`。
- 默认：05/06 只有 view/upload；delete/restore/purge 默认关闭；admin 按大区/办事处/部门/个人勾选，可跨大区。
- 历史 1 本书/1 篇内容归公司根节点；默认 all 公司级可见，可收窄。

### 版本/编辑/预览
- 重命名：允许，后缀锁定，仅白名单后缀。
- 替换：同后缀/同类型，生成新版本；激励佐证锁定替换。
- 在线编辑：不做 WPS 式内容编辑；只做重命名/替换/版本。
- 版本：所有版本字节保留；最近 N 版热存，旧版冷存储；版本下载/回滚；回滚权限带数据范围。
- 预览：图片 WebP 多尺寸；视频封面 + 5 秒小 MP4；PDF/Office 首页封面；CAD/压缩包/音频回退图标；私有缩略图签名 URL；异步生成+CDN。
- 上传：200MB 上限；断点续传、秒传（md5）、病毒扫描。

### UI
文件中心页签：公共 / 私人 / 四项激励 / 法布施 / 分享给我 / 回收站；同一套组件。

## 五、组织层级与移动

### 组织树
- `sys_dept` 通用树：`parent_id/dept_type/dept_path/dept_level`；部门可套部门，任意父级。
- `dept_type` 字典：公司/大区/办事处/部门。
- 数据范围：`region`=最近大区祖先；`office`=最近办事处祖先；`dept`=当前部门子树；`team`=`manager_id` 链；`company`=根；`self`=本人；`custom`=勾选组织。
- 10 万人员/500 部门：闭包表/物化路径 + 缓存。

### 组织移动
- 改 `parent_id`，批量更新子树 `dept_path/dept_level`；事务+子树锁；大子树异步。
- **只改当前数据**：客户/文件/激励/任务/提醒/审批/财务按新组织改派；历史/已删/归档不动。
- 移动前影响清单：各模块条数；一级审批；`sys_dept_move_log` 记录/回滚。
```sql
CREATE TABLE sys_dept_move_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  dept_id BIGINT NOT NULL,
  from_parent_id BIGINT NULL,
  to_parent_id BIGINT NULL,
  before_path VARCHAR(1000) NULL,
  after_path VARCHAR(1000) NULL,
  affected_json JSON NULL,
  operator_id BIGINT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  status VARCHAR(20) NOT NULL DEFAULT 'completed'
);
```

## 六、离职交接

```sql
CREATE TABLE biz_handover (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  tenant_id BIGINT NOT NULL,
  from_user_id BIGINT NOT NULL,
  to_user_id BIGINT NOT NULL,
  status VARCHAR(20) NOT NULL DEFAULT 'draft',
  scope_json JSON NULL,
  stats_json JSON NULL,
  created_by BIGINT NULL,
  approved_by BIGINT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  completed_at DATETIME NULL
);
CREATE TABLE biz_handover_item (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  handover_id BIGINT NOT NULL,
  biz_type VARCHAR(20) NOT NULL,
  biz_id BIGINT NOT NULL,
  action VARCHAR(20) NOT NULL COMMENT 'transfer/share/reassign',
  status VARCHAR(20) NOT NULL DEFAULT 'pending',
  UNIQUE KEY uk_handover_item (handover_id, biz_type, biz_id)
);
```
- 发起：离职本人/管理员/对应行政；审批一级：销售总监/大区行政，admin 可配。
- 继任人可跨区；按继任人自身角色/范围。
- 客户 owner→继任人；任务 assignee→继任人；私有文件 owner/uploader→继任人；公共/激励/法布施共享给继任人；激励保留原作者；提醒跟客户；审批 pending 转交；角色/权限不复制。
- 失败提醒、可回滚；交接单审计。

- admin 可改审批流；现有已审批数据不受影响（当前无 pending）。
- UI 去掉多级/会签配置；保留审批历史。

## 十、验收用例（摘要）

1. 客户名称：全半角/大小写/空格/中文括号归一化；重复新建 400；豁免客户可保留；删除后同名可建；恢复撞名 400。
2. 权限：勾/取消 `fabushi:file:delete` 同 token 403↔200；角色/人员/数据范围（大区/办事处/部门/个人）生效。
3. 文件：法布施页签可见；上传/删除/恢复/彻底删；配额；版本回滚；重命名后缀锁定；200MB 上传/断点续传；缩略图/5 秒视频。
4. 回收站：导出 ZIP（7 天过期、审计）；恢复回原客户；彻底删后不可恢复；冷归档可查。
5. 交接：跨区继任人；客户/任务/文件/激励自动共享/改 owner；审批一级；失败回滚。
6. 组织移动：影响清单；当前数据改派；历史不动；日志/回滚；一级审批。
7. 审批：所有流程一级；admin 配审批人；无多级/会签。
8. 性能：500 并发；文件列表 P95 < 200ms（目标）；权限缓存命中率；慢查询 0。

## 十一、生产边界

- 本稿不执行任何生产写：旧数据清理、组织移动、交接、权限变更均需单独授权。
- 旧数据清理先在测试库演练，出差异报告；生产前全库+NASS 备份，建议第二份离线。
- 迁移脚本按 Flyway 版本化，支持回滚；灰度发布，权限/文件/回收站分开关。
