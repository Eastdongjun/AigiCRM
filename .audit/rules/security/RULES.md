# 安全规则(项目沉淀,源自六轮审计实证)

## 认证与会话
- SEC-01 JWT:仅 401 踢登录;403=已认证无权,不得登出(2026-09-22 实证修复)
- SEC-02 改密撤销:pwd_changed_at vs token iat,时区必须 Asia/Shanghai 与 DB 一致
- SEC-03 登录限流:账号级+IP 级双计数;成功登录清账号计数
- SEC-04 冷启会话:入口页须支持有效令牌自动回填(auth/info),不得强制重登
- SEC-05 令牌分环境存储(AIGICRM_TOKEN::<base>),demo/测试/生产隔离

## 授权(服务端必须复核,前端隐藏≠权限)
- SEC-10 每个写端点:admin ∨ 功能权限码 ∨ 对象归属 三选一守卫,禁止短路写法
  `if(isOrgAdmin() && !canManageUser(id))` 型守卫=对非管理员整体短路(DeepSeek P0-1 实证)
- SEC-11 水平越权(IDOR):taskId/customerId/recordId 等路径参数必须做归属校验
- SEC-12 数据范围:WithinGroup 全局表 null=all 会放大到全平台,必须显式收窄
- SEC-13 集团/租户隔离:列表、统计、导出、提醒四链路全部带租户过滤(双集团用例守卫)
- SEC-14 对象级授权边界:dept/position/config/role 编辑端点不得只挡功能码不校验对象(已知排队项)
- SEC-15 状态机:审批中/在途票款等状态下的删除、转移必须被服务端拒绝

## 注入与数据
- SEC-20 SQL 一律参数绑定;动态排序/IN 列表白名单化
- SEC-21 上传:类型/大小白名单,路径不可控,ACL 私有读
- SEC-22 文件引用:记录引用的文件 ID 必须存在且属于上传人(新增引用时校验;存量引用以原上传校验为准)

## 密钥
- SEC-30 凭据只存服务端 .env(600),禁止入库/入证据文件
- SEC-31 备份档/证据导出前跑 secret 自检三轮定位(外发档零泄漏先例)
