## 0. 本次确认的产品口径

1. **集团**：集团信息**可见**；**只有管理员可以修改**；**管理员可以创建**；系统**只有一个集团**。
2. **字段码**：`customer:date:edit`、`customer:invoice-date:edit` 等字段级权限码必须**纳入权限中心**，可配置、可解释、有依赖，不能成为“勾了不生效”的死配置。
3. **总体目标**：不是逐条打补丁，而是把权限体系收敛成“**功能码（含字段码）× 数据范围 × 归属/授权 × 集团边界**”四层模型，单一事实源、配置期可校验、运行期 fail-closed、错误可机读。

## 2. 目标模型

### 2.1 权限点五要素（单一事实源）

每个权限码登记：

| 要素 | 取值 | 用途 |
|---|---|---|
| code | 如 `customer:date:edit` | 唯一标识，注解/DB/前端/文档同源 |
| type | ENTRY / MENU / BUTTON / **FIELD** | 决定页面展示与依赖规则 |
| module | 客户/文件/激励/学分/系统… | 权限中心分组 |
| parentCode | 如 `customer:edit` | 字段码/附属码必须依附父功能码 |
| scopeAxis | `(module, action)` 或 `INHERIT` / `NONE` | 是否显示数据范围、范围如何生效 |
| constraints | adminOnly / requiresOrgAdmin / deprecated / noEndpoint | 防误配、契约校验 |

落地：`PermissionRegistry`（Java 常量或 `sys_permission_meta` 表）为源，生成前端常量、权限字典、菜单种子；CI 校验 `sys_menu`、`@PreAuthorize`、前端常量三方一致。

### 2.2 集团模型（按本次口径）

| 操作 | 规则 | 实现层 |
|---|---|---|
| 读 | **登录即可见**（列表/选择器）；管理页可由 `system:group:view` 控制，默认授予所有角色 | Controller 去掉方法级码或改为登录校验；页面保留 |
| 创建 | **仅平台管理员**；且 `sys_group` 行数 = 0 时允许，否则 400「单集团部署仅允许一个集团」 | SysGroupService.create + Controller |
| 修改 | **仅平台管理员**；禁止改 `group_code`；禁止把最后一个活跃集团 `status=0` | SysGroupService.update |
| 删除 | **仅平台管理员**；保留“最后一个活跃集团不可删/禁用”守卫（防御性，单集团下前端不显示入口） | SysGroupService.delete |
| 前端 | 页面可见；新增按钮：admin 且 0 集团；编辑：admin；禁用：admin 且活跃集团 >1（单集团不显示）；状态开关：唯一活跃集团时禁用 | group.vue |

> 单集团约束放在应用层（`count()>=1` 拒绝创建）。未来多租户需要改为配置开关/租户套餐，不能只删守卫。

### 2.3 字段码模型

| 字段码 | 父功能码 | 作用字段 | 数据范围 | 运行位置 |
|---|---|---|---|---|
| `customer:date:edit` | `customer:edit` | 注册日 registerDate | **继承 customer:edit 范围**，不单独配置 | PUT /api/customer/{id} 内 Service 字段守卫 |
| `customer:invoice-date:edit` | `customer:edit` | 最近开票日 lastInvoiceDate | 继承 customer:edit 范围 | 同上 |
| `contact:view` | `customer:view` | 联系人 Tab 数据可见 | 继承 customer:view 范围 | GET /customer/{id}/contacts 返回空列表掩码 |
| `finance:view` | `customer:view` | 发票/回款可见 | 继承 customer:view 范围 | GET invoices/payments 空列表掩码 |

规则：

1. 字段码是**从属码**：授予字段码必须同时授予父功能码；取消父码时字段码一并取消。
2. 字段码**不单独出现范围轴**；权限中心显示“跟随客户编辑范围”。
3. 字段判断统一走 `FieldPermissionService`，错误码 `FIELD_PERM_REQUIRED`，HTTP 400。
4. 字段码仍保留在 `sys_menu`（menu_type=3）以便角色勾选；但 UI 必须打「字段级」标签、置灰依赖、显示继承范围。

### 2.4 错误语义

| 场景 | HTTP | errorCode | 示例 |
|---|---|---|---|
| 无功能码 | 403 | `PERM_DENIED` | 缺少「客户编辑」功能权限 |
| 有码但数据范围外 | 403 | `DATA_SCOPE_DENIED` | 只能编辑自己的客户 |
| 字段码缺失 | 400 | `FIELD_PERM_REQUIRED` | 注册日录入后仅总监或行政可修改 |
| 仅管理员 | 403 | `ADMIN_ONLY` | 仅系统管理员可触发该任务 |
| 需组织管理员 | 403 | `ORG_ADMIN_REQUIRED` | 无权操作该用户（需组织管理员） |
| 废弃/无端点码 | 400/404 | `DEAD_CODE` | 该权限码已废弃/无对应功能 |

`Result<T>` 增加 `errorCode`；`GlobalExceptionHandler` 与 `@PreAuthorize` 失败统一映射；前端 `request.js` 按 errorCode 给提示，不再靠文案猜。

## 3. 分阶段修复方案

### P0（1–2 天，先止血 + 落实本次口径）

#### P0-1 集团写操作管理员化 + 单集团

**后端**：

```java
// SysGroupService
private void requirePlatformAdmin() {
    if (!SecurityUtils.isAdmin()) throw new BusinessException(403, "仅系统管理员可管理集团");
}
public void create(SysGroup g) {
    requirePlatformAdmin();
    if (groupMapper.selectCount(null) >= 1)
        throw new BusinessException(400, "单集团部署仅允许一个集团");
    // 原有编码唯一校验 + insert
}
public void update(SysGroup g) {
    requirePlatformAdmin();
    SysGroup existing = groupMapper.selectById(g.getId());
    if (existing == null) throw new BusinessException(404, "集团不存在");
    if (g.getGroupCode() != null && !g.getGroupCode().equals(existing.getGroupCode()))
        throw new BusinessException(400, "集团编码创建后不可修改");
    if (g.getStatus() != null && g.getStatus() == 0) {
        Long active = groupMapper.selectCount(new LambdaQueryWrapper<SysGroup>().eq(SysGroup::getStatus, 1));
        if (active != null && active <= 1) throw new BusinessException(400, "不能禁用唯一集团");
    }
    // updateById
}
public void delete(Long id) { requirePlatformAdmin(); /* 现有唯一活跃集团守卫 */ }
```

**Controller**：`list` 改为登录即可（`@PreAuthorize("isAuthenticated()")` 或去掉）；create/update/delete 保留 `system:group:*` 注解并叠加服务层 admin 硬校验（双闸）。

**测试**：
- 非 admin 调用 create/update/delete → 403；
- admin 在已有集团时 create → 400；
- admin 把唯一活跃集团 status=0 → 400；删除 → 400；
- 任意登录用户 GET 列表 200；
- 浏览器：非 admin 页面无新增/编辑/禁用；admin 单集团只显示编辑。

**风险/回滚**：多租户未来需改配置开关；回滚只回滚代码，无数据变更。

#### P0-2 集团页面收敛

`group.vue`：

```js
const isAdmin = computed(() => userStore.isAdmin) // 或 roles 包含 admin
const canAddGroup = computed(() => isAdmin.value && groups.value.length === 0)
const canEditGroup = computed(() => isAdmin.value)
const canDeleteGroup = computed(() => isAdmin.value && activeGroupCount.value > 1)
const canToggleStatus = computed(() => isAdmin.value && activeGroupCount.value > 1)
```

编辑弹窗状态开关在单活跃集团时禁用并提示「唯一集团不可禁用」。

#### P0-3 字段码登记 + 依赖校验 + 菜单修正

**迁移** `V2026.11.15.x__permission_field_codes.sql`：

```sql
-- 字段码挂在 customer:edit 下、可见；名称标注字段级
UPDATE sys_menu SET parent_id = 41, visible = 1, menu_name = '修改客户保护日期（字段）'
 WHERE permission = 'customer:date:edit';
UPDATE sys_menu SET parent_id = 41, visible = 1, menu_name = '最近开票日编辑（字段）'
 WHERE permission = 'customer:invoice-date:edit';
-- 清理“字段码无父码”的历史角色绑定（先记录再删）
DELETE rm FROM sys_role_menu rm JOIN sys_menu m ON m.id = rm.menu_id
 WHERE m.permission IN ('customer:date:edit','customer:invoice-date:edit')
   AND NOT EXISTS (SELECT 1 FROM sys_role_menu rm2 JOIN sys_menu p ON p.id = rm2.menu_id
                   WHERE rm2.role_id = rm.role_id AND p.permission = 'customer:edit');
```

**依赖表**（注册表/常量）：

```java
Map.of(
  "customer:date:edit", "customer:edit",
  "customer:invoice-date:edit", "customer:edit",
  "contact:view", "customer:view",
  "finance:view", "customer:view"
)
```

**saveRoleMenus 校验**（在 includedCodes 计算后、写库前）：

```java
for (var e : REQUIRES.entrySet()) {
    if (includedCodes.contains(e.getKey()) && !includedCodes.contains(e.getValue())) {
        throw new BusinessException(400,
            "字段/附属码 " + e.getKey() + " 需同时勾选父功能码 " + e.getValue());
```

取消父码时：后端直接 400 要求先取消子码，或自动移除子码并提示；建议后端自动移除 + 返回 warning，前端同步取消勾选。

#### P0-4 字段码在权限中心可见可配

- 后端新增 `GET /api/system/perm-center/meta`，返回权限点元数据（type/parentCode/module/scopeMode/adminOnly/deprecated/description）。
- `usePermissionData.permModules` 合并元数据：字段码加 `字段级` 标签；父码未勾时子码 `disabled`；字段码不渲染范围下拉，改为灰字“跟随客户编辑范围”。
- `PermScopeManager` 行卡显示依赖提示；取消父码时自动取消子码并提示。

#### P0-5 字段权限服务收口

新增 `FieldPermissionService`：

```java
public boolean canEditRegisterDate() { return SecurityUtils.hasAuthority("customer:date:edit"); }
public boolean canEditInvoiceDate() { return SecurityUtils.hasAuthority("customer:invoice-date:edit"); }
public void requireRegisterDate() {
    if (!canEditRegisterDate())
        throw new BusinessException(400, "FIELD_PERM_REQUIRED", "注册日录入后仅总监或行政可修改");
}
```

`CustomerService.protectCustomerDateFields` 改为调用服务；补单测（两码组合、撤销、admin）。

#### P0-6 错误码语义化

- `Result<T>` 增加 `errorCode` 字段（向后兼容）。
- `BusinessException` 增加 `errorCode` 构造；`GlobalExceptionHandler` 输出。
- `AccessDeniedException` → 403 + `PERM_DENIED`；`OrgAdminService` 拒绝 → `ORG_ADMIN_REQUIRED`；字段 → `FIELD_PERM_REQUIRED`；admin-only → `ADMIN_ONLY`。
- 前端 `request.js` 按 errorCode 分支提示；测试按 errorCode 断言，不再靠文案。

#### P0-7 死码/错位码清理与登记

- 迁移：`incentive:view-all/view-shared` 保持/置 `status=0`；`system:menu:edit`、`sea:pool:delete` 无 sys_menu 行 → 在权限字典标注“不存在/由 sea:view 承载”；`system:role:grant` 标注“内部旁路码，无独立端点”；`incentive:*:export` 标注“前端导出，无后端端点”。
- 契约脚本：每个 `@PreAuthorize` 码必须在注册表登记；每个注册码必须有端点或显式 `noEndpoint/adminOnly/field` 白名单；否则 gate 失败。
- 修正 4 条历史误判：`system:position:rule:edit`、`system:scope:grant`、`system:user:assign` 端点存在，应按正确路径重跑；`system:task:run` 旧 27 行 NO_ENDPOINT 作废，以新口径为准。

### P1（3–5 天，模型收敛）

1. **权限点注册表单一事实源**：Registry + 生成器（前端常量/字典/菜单种子），CI 三方一致。
2. **adminOnly / requiresOrgAdmin 元数据**：矩阵标签、禁勾、403 机器码；`system:user:edit/delete` 标注“需组织管理员”，`system:task:run`/集团写操作标注“仅管理员”。
3. **数据范围配置校验**：custom 必须有 role_org；region/office 校验成员祖先；保存前影响预览；空范围警告。
4. **写操作串行化 + 缓存事务化**：按 roleId/roleCode 分段锁；`afterCommit` 失效缓存；并发单测。
5. **范围轴后端下发**：删除前端硬编码 `PERMISSION_SCOPE_TARGETS`，由 meta 接口提供，字段码 `scopeMode=INHERIT`。

- 单集团创建限制会影响未来多租户，需产品确认长期开关；

- 范围校验可能拦住存量配置，需提供豁免清单/批量修复。

回滚：

- 代码按项回滚（每项独立提交）；
- 迁移提供反向 SQL；
- 不删除业务数据，只改菜单元数据与角色绑定（可重放）。
