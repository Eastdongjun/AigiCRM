# AIGICRM 四套指标口径定义

> **版本**:2026-09-19 · **依据**:业务决策会议题三裁决 · **代码核验**:2026-09-19(逐条比对源码)
> **用法**:本文件是四套指标的权威口径;任何修改须走业务决策会,代码实现以本文件为准。

---

## 1. 四项激励积分

| 维度 | 口径 |
|---|---|
| **对象** | 客户 × 月 |
| **周期** | 自然月(1日~月末) |
| **计入条件** | 上传合格佐证(安装前/安装中/安装后/跟踪资料),每条记录独立计分 |
| **去重** | **不去重**——上传一次记一次分(裁决) |
| **分类** | 保留四项原分类(产品试点/交流拜访/外出参观/跟踪记录),**不合并为通用总积分** |
| **修改/删除** | 记录可追加文件、可删除(删除后积分重算);不静默覆盖历史 |
| **代码实现** | `IncentiveService.addRecord()` 每次插入新记录,`recalculateAllScores()` 按最新规则重算 |

**验证**:`✅ 上传一次记一次分` — 每次 addRecord 独立 insert,无幂等键。

## 2. 客情五项评分

| 维度 | 口径 |
|---|---|
| **对象** | 客户 |
| **周期** | 实时(无周期概念,最新评估即生效) |
| **计分方式** | 手动评估,每项 0~3 分,共五项(高层客情/渠道编码/基层覆盖/产品渗透/项目资金) |
| **覆盖规则** | **新评覆盖旧评**(裁决)——upsert 语义,不保留历史版本 |
| **总分** | 五项之和,0~15 分 |
| **代码实现** | `CustomerService.saveIndicator()` upsert(存在则 updateById,不存在则 insert) |

**验证**:`✅ 新评覆盖旧评` — saveIndicator 是 upsert;saveRelationshipScore 同口径。

## 3. 核心客户判定

| 维度 | 口径 |
|---|---|
| **对象** | 客户 |
| **周期** | **实时**(裁决)——任一输入变更立即重算 |
| **判定条件** | 开票总额 ≥ 100万 **且** 回款总额 ≥ 100万 **且** 客情五项总分 ≥ 12 |
| **降档** | 即时降档(不等到月末) |
| **计算路径** | 开票增/删、回款增/删、指标保存、客情分修改——六条路径全部触发 `recalculateCoreStatus()` |
| **代码实现** | `CustomerService.recalculateCoreStatus()` 查 sumAmount → 与阈值比较 → 写 `is_core` 字段 |

**验证**:`✅ 即时计算` — PR-17(a843f3a)补齐了 saveRelationshipScore 缺失的触发;
其余五条路径(开票增删/指标保存/回款增删)此前已各自触发。

**阈值配置**:100/100/12 当前为代码常量(`CustomerService:1178-1179`);
如需管理员可配,走 sys_config + 规则版本化(PR-24 机制已就绪),需业务会确认。

## 4. 阅读统计

| 维度 | 口径 |
|---|---|
| **对象** | 人 × 月 |
| **周期** | 自然月 |
| **计入条件** | 打开激励资料详情页(markRead) |
| **去重** | **重复打开计一次**(裁决)——同一人对同一条资料当月只计一次 |
| **与业绩的关系** | **阅读 ≠ 业绩**——阅读统计仅反映信息触达,不计入激励积分/排名 |
| **代码实现** | `IncentiveService.markRead()` INSERT ... ON DUPLICATE KEY UPDATE(幂等) |

**验证**:`✅ 重复打开算一次` — ON DUPLICATE KEY UPDATE read_at=CURRENT_TIMESTAMP,不新增行。

## 5. 已超期指标(2026-10-09 裁决)

| 维度 | 口径 |
|---|---|
| **判据** | `expire_date < 今日` 且 `status NOT IN (sea, archived)` 且 `deleted=0`(受数据范围控制) |
| **适用范围** | **三处同判据**:工作台 hero「已超期」、统计页「已超期」、客户列表 status=expired 钻取/快速筛选/统计卡 |
| **不含公海** | 到期客户会被凌晨任务转入公海(status→sea),公海客户无负责人不计数——工作台旧口径(protection_status='expired' 不排公海)已废弃(曾致工作台 29 vs 统计页 2 两页不一致) |
| **代码实现** | `CustomerService.countExpiredByScope()`(工作台)与 `applyFilterConditions` status='expired' 翻译(列表/统计卡),与 `StatisticsQueryService` 统计页完全同判据;2 测试钉(CustomerServiceTest) |

**验证**:`✅ 三处同判据` — 2026-10-09 测试环境实测两页数字一致。

## 修改流程

1. 任何口径变更须先经业务决策会裁决;
2. 裁决后修改本文件 + 对应代码实现;
3. 走标准七步闭环(baseline → 修改 → 全量门禁 → 证据归档);
4. 规则参数变更(如阈值)自动记录到 `sys_rule_version`(PR-24 机制)。
