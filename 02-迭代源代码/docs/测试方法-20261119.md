## 0. 测试分层（证据阶梯）

按“发现问题的成本”从低到高分层，**低层全绿不能替代高层**；登录/权限/文件/审批等关键路径必须有 L4 或 L5 证据。

| 层 | 名称 | 主要手段 | 运行时机 | 证据 |
|---|---|---|---|---|
| L1 | 单元测试 | JUnit 5 + Mockito；Vitest | 每次改代码 | 测试报告、失败断言 |
| L2 | 契约/静态检查 | `scripts/check-*` 70+ 契约、ArchUnit、vue-tsc 基线、API 清单 | 每次交付（gate） | 契约输出、行号 |
| L3 | 集成/权限行为 | `PermissionBehaviorMatrixTest`、`PermissionMatrixTest`、权限矩阵 4 万例、DB 空库重放 | 权限/迁移改动 | 矩阵 jsonl、重放末态 |
| L4 | 运行态 E2E | Playwright（PC）、miniprogram-automator（MP）、文件权限五段 E2E | 页面/跨端/文件改动 | 截图、console 零错误、接口断言 |
| L5 | 环境冒烟/发布验证 | `smoke-test.sh`、deploy 健康检查、生产只读复核、回滚演练 | 每次发布 | 状态码、jar/dist md5、回滚路径 |

## 2. L1 后端单元/切片测试

```bash
cd aigicrm-backend
mvn -q test                 # 全量：1220 tests / 127 classes
mvn -q -Dtest=类名 test      # 单类（先跑最小相关测试）
mvn -B -q verify            # 全量 + 打包 + ArchUnit 分层约束（CI 同款）
```

### 关键测试类（改动对应位置必跑）

| 测试 | 钉住什么 |
|---|---|
| `security/PermissionBehaviorMatrixTest` | `@PreAuthorize` 真实求值：角色 × 权限码 × 允许/拒绝 |
| `security/UserDetailsServiceImplTest` | 登录装载、任职组织、权限上下文 |
| `security/PermissionCacheServiceTest` | 权限缓存 key/TTL/失效 |
| `architecture/ArchitectureTest` | 分层依赖（Controller→Service→Mapper），禁止反向依赖 |
| `StabilityInvariantTest` | 迁移冻结 `INV-MIG-001`、唯一键/不变量 |
| `module/**/…ControllerPermissionTest` | 各模块接口权限矩阵（统计/激励/文件夹等） |
| `FabushiMonthlyReportTest` 等 | 业务口径与时间边界（禁止依赖 `now()` 的跨日抖动） |
| `FolderAclServiceTest` / `FolderPermission*Test` | 文件夹 ACL/越权（403/404/200） |

### 写法要求

- 断言行为，不测实现细节；异常路径必须显式断言（不能只断言不抛）。
- 时间相关用固定时钟/固定日期，禁止 `LocalDateTime.now()` 直接进断言（曾出现 23:xx 跨日假红）。
- Mock 只替外部依赖，不替被测业务；**禁止**用 mock 顶替权限求值（权限必须走 `PermissionBehaviorMatrixTest` 的真实求值）。

## 5. L3 权限矩阵（4 万例）

### 5.1 角色级回归（轻量，适合每次权限改动）

```bash
cd 02-迭代源代码
AIGI_TEST_USER=admin AIGI_TEST_PASS=*** bash scripts/verify-perm-matrix.sh
```

核对三件事：
1. 每个角色 `/api/auth/info` 生效权限码 == 库内 `sys_role_menu` type=2 绑定集；
2. 勾选/撤销往返：403 → 200 → 403（真实请求）；
3. `sys_role_menu` 无孤儿绑定。

### 5.2 全量矩阵（重量，权限内核/发布前）

执行器：`scripts/fabushi/permission_matrix_v2.py`（A 四认证态 / B 他人资源越权 / C 自身资源正面 / D 全权限角色范围轴），
审计器：`scripts/fabushi/permission_matrix_audit.py`。

```bash
python3 scripts/fabushi/permission_matrix_v2.py \
  --base http://111.229.37.220 \
  --secret-file /tmp/jwt_secret.txt \
  --users /tmp/perm_users.json \
  --temp-users /tmp/temp_users.json \
  --pools /tmp/pools.tsv \
  --out test-results/permission-matrix/full-$(date +%Y%m%d).jsonl
```

- 账号/角色/资源池文件由上一轮审计准备（`--temp-users` 为测试服临时“全权限角色 × 5 种数据范围”用户）；
- 生产环境**禁止**执行；测试服执行后必须清理临时角色/用户；
- 审计口径（2026-11-16 基线）：planned **48,580**、真实执行 **43,991**、匹配 40,938、需复核 2,654、**不匹配 0**；
- 旧版“42,511 例真实请求”把 SKIP 计入，已废弃；报告里必须区分 **planned / executed / skipped**。

**判定纪律**：
- 未执行（SKIP/N-A）单列，不能算“通过”；
- 401/403/404 要按“认证态/资源是否存在”分类，不能一律当失败（会产生几千条假 mismatch）；
- 网络错误（`ERR:URLError`）必须重试，不能计为业务不匹配；
- 每行保留 `mode`、实际请求路径、注入资源（`实体#id@owner`）、执行标记，便于复核。

## 12. 证据与报告格式

每条结论必须可复现：

```text
[命令] bash scripts/gate.sh --quick
[退出码] 0
[结果] PASS=8 FAIL=0
[证据] /tmp/gate-*.log 或 test-results/...
```

报告表：

| 门禁 | 命令 | 退出码 | 结果 |
|---|---|---|---|
| 修改范围 | `git diff --check` | 0 | PASS |
| 后端测试 | `mvn -q test` | 0 | PASS（1220/0/0/0） |
| 前端测试 | `npm test` | 0 | PASS（340） |
| 构建 | `npm run build` | 0 | PASS |
| 门禁 | `bash scripts/gate.sh` | 0 | PASS=9 FAIL=0 |
| 运行态 | 生产/测试接口与页面 | — | PASS / BLOCKED |

最终状态只能 `PASS` / `FAIL` / `BLOCKED`；无法验证的写 `BLOCKED` 并说明缺什么。

## 13. 常见假绿与反模式（发现即打回）

1. 只跑单文件/单测就宣称“系统行为对”（缺 L3/L4）；
2. 契约自指、无负例（改坏也不会红）；
3. mock 顶替权限求值、mock 顶替真实下载；
4. 把 SKIP/未执行计入“通过”（矩阵旧口径 42,511 的教训）；
5. 删断言/降断言/关规则/加 `@ts-ignore` 换绿；
6. 用“更新文档”代替修代码；
7. 时间/跨日依赖导致偶发假红（固定时钟）；
8. 前端 URL 只在运行时拼、单测 mock 不校验（双 `/api` 404 的教训，已加 `check-ui-api-prefix.py`）；
9. 生产发布后不复核（MIME、404、401、日志 ERROR、5xx）；
10. 证据只在聊天里、不在项目内（必须落 `test-results/` 或 `docs/`）。
