# 小程序原型状态覆盖矩阵

> 目的：解释原型基准 51 张截图与当前 45 个独立注册页面之间的差额。通用状态不重复注册为页面，但必须在真实页面中可进入、可验证。

## 当前口径

| 类别 | 数量 | 说明 |
| --- | ---: | --- |
| 独立页面 | 45 | 以 `aigicrm-miniprogram/app.json` 的 `pages` 为准 |
| 原型截图基准 | 51 | 历史原型截图总数 |
| 通用/页面状态差额 | 6 | 不新增路由，绑定到已有页面状态 |

## 六类状态

| 编号 | 状态 | 代码证据 | 验收方式 | 当前状态 |
| --- | --- | --- | --- | --- |
| S1 | 加载中 | `pages/*/index.wxml` 的 `loading` 分支 | 在页面请求期间检查加载提示不遮挡操作区 | 已实现 |
| S2 | 空数据 | 客户、审批、公海、提醒、文件、统计等页面的 `length===0` 分支 | 使用空响应或演示数据切换验证空状态文案 | 已实现 |
| S3 | 请求失败 | 页面 JS 的 `showError(error, ...)` 分支 | 断开接口或返回非 2xx，确认错误提示且页面可恢复 | 自动化回归已覆盖，待人工全量验收 |
| S4 | 无权限/未登录 | 页面 JS 的 `hasPermission(...)` 守卫与登录跳转 | 使用无权限身份访问页面，确认不展示敏感数据 | 已实现；QA API 矩阵已验证（登录 200、权限数 0、受保护接口 403），浏览器 UI 点击矩阵待验收 |
| S5 | 详情不存在 | 详情页的 `!loading && !detail/record/approval` 分支 | 使用不存在 ID 访问详情，确认空详情而非白屏 | 已实现 |
| S6 | 操作提交失败/恢复 | 审批、捞取、反馈、分享等动作的 `catch/finally` 分支 | 返回失败后检查 loading 复位、错误可见、可再次操作 | 自动化回归已覆盖，接口故障注入与人工验收待完成 |

## 结论

当前页面数量应报告为 **45 个独立页面**，原型覆盖报告为 **45/51（88.2%）**。这不是把状态页面遗漏后强行合并；而是明确区分“路由页面”与“同一页面的状态截图”。补齐剩余原型验收时，优先做 S1-S6 的人工状态截图和故障注入证据；S4 已有 QA API/后端证据，仍需补浏览器 UI 点击证据。
