# 小程序 PC 对齐手工验收清单

## 使用条件

- 微信开发者工具已导入 `/Users/dongjun/东来/项目/02-已上线/01-AIGICRM/02-迭代源代码/aigicrm-miniprogram`；该目录必须直接包含 `app.json` 和 `project.config.json`。
- 导入前运行 `bash scripts/check-wechat-project-root.sh`，避免误打开上一级源码目录或其他项目。
- `config/env.js` 已临时设置 `demoMode: false`，并指向本地或测试后端。
- 使用测试账号，不记录密码、token 或 Cookie。
- 每项填写“通过/失败/阻塞”和日期；失败项附现象与接口状态码，不附敏感响应头。
- 如果需要扫码入口，优先使用开发者工具“预览/真机调试”；CI 预览二维码按 `docs/miniprogram-release-runbook.md` 的 `MINIPROGRAM_PRIVATE_KEY=... npm run preview` 生成，密钥不得放入仓库。
- 页面自动化前先运行 `02-迭代源代码/scripts/dev-verify.sh changed`；其中 `check-mobile-pc-api-parity-contract.sh` 会检查客户、激励、文件、公海、统计等已实现移动端模块与 PC 前端共享同一批后端路径，并确认 PC-only API 没有进入小程序 API 层。
- 页面层可先运行 `cd scripts/miniprogram && npm run verify:mobile-parity` 做 DevTools 自动化预检；该聚合脚本覆盖首页、客户、激励、文件、审批、公海、统计、核心指标、排行、提醒、资料、登录、反馈/通知等移动端 PC 对齐场景，并自动断言应用中心不会暴露客户导入/导出、系统管理、配置、ACL、学分录入、批量操作等 PC-only 入口。
- 激励附件专项可单独运行 `npm run verify:incentive-attachments` 复测上传页、列表页、详情页和客户时间轴附件 UI；自动化不能替代真机选择文件、提交记录、真实下载保存和同一后端数据对账。
