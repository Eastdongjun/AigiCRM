## 三、补预置 runbook（新镜像 tag 首次部署前执行）

```bash
# 首选：生产机直连拉取（加速器生效时）
ssh_prod "docker pull <image:tag>"
# 若拉取超时（A2 窗口实测形态）→ 从已有该镜像的机器中转：
#   源机:  docker save <image:tag> | gzip > /tmp/img.tgz
#   本地:  scp 拉回 → scp 推生产
#   生产:  gunzip -c /tmp/img.tgz | docker load && docker images | grep <image>
# 验证: docker run --rm <image:tag> --version（或等价无副作用命令）
```

注意事项：
1. 版本对齐：flyway 镜像 tag 与 `pom.xml` flyway-core 版本线保持一致（当前 9.22.3）；mysql 与生产实例 8.0.28 对齐（不追新）。
2. 预置后在本文件登记（镜像/tag/ID/日期/经办）。
3. Dockerfile 基础镜像（`eclipse-temurin` 等）变更时，`deploy-backend.sh` 的经典构建器（DOCKER_BUILDKIT=0）同样依赖本地缓存——新基础层同样走本 runbook。
