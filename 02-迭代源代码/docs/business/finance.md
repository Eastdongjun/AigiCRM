# 财务记录(开票/回款)

> 来源锚点:`CustomerController` 财务端点、`BizInvoice/BizPayment` 实体、`CustomerService` 保护期公式。核实日期 2026-09-24。

## 1. 数据模型

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| 开票 `biz_invoice` | invoice_date/invoice_number/invoice_type/invoice_company/amount/created_by | 一客户多票 |
| 回款 `biz_payment` | (同构:日期/金额/经手) | 与开票分列 |

财务记录挂在客户详情财务页签,PC 与小程序同源。

## 2. 权限

- 读:`customer:view` + `finance:view`(无 finance:view 时页签返回空,不报错)。
- 增删:`finance:manage` **或**(`customer:edit` + `finance:view`)——V2026.09.23.4 起 finance:manage 为可勾选专职授权码,两类持有者都可操作。

## 3. 与保护期的联动(核心业务规则)

```
最近开票日(last_invoice_date)= MAX(该客户全部非作废开票的 invoice_date)
到期日 = COALESCE(最近开票日, 注册日) + 360 + 累计已批延期
```

> **【裁决 2026-09-24】最近开票日=纯推导字段**:以最后一次开发票的日期为准,任何角色(含
> admin/customer:date:edit 持有者)不得经客户编辑接口直改,客户创建时也不接受表单直带——纠错一律走
> 财务页发票补录/作废,全程留痕(替换原"总监或行政可改"双轨:人工值会被下次开票重算静默覆盖)。
> **发票/回款可删但必留痕(裁决当日二次更新)**:任何状态均可删除,**必填删除原因**;删除时写 sys_log
> 审计快照(票号/日期/金额/状态/原因/操作人),数据行 @TableLogic 逻辑删保留可回查;保护期自动回算。
> 更正常规口径仍推荐"作废"(voided 不进统计与保护期)。V2026.09.24.1 已为 258 个 legacy 客户回填
> "历史导入"票承接旧手工日期,切换零行为变化。

- **新增开票 → 最近开票日前移 → 到期日顺延**(保护期随最新开票滚动);
- **作废开票 → 回算**最近开票日(可能变早),到期日随之下调;已批延期是否收回见延期裁决(待定,当前不收回)。
- 开票日因此成为保护期的核心输入——纯推导模型下无需"注册日/开票日录入权限",注册日仍为受控字段(customer:date:edit:总监 0/行政 05/admin)。

## 4. 与提醒的联动

- 从未开票 → `invoice_never` 提醒;最近开票距今 >365 天 → `invoice_overdue` 提醒(见 [reminder.md](reminder.md) §1)。
