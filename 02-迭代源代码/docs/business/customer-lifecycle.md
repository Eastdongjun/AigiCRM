# 客户生命周期与保护期

> 来源锚点:`CustomerExpireTask`(每日凌晨 2 点任务)、`ApprovalService.applyApprovalAction`(审批执行)、`CustomerService`(创建/更新/公海)。核实日期 2026-10-18(延期规则收敛 + 公海删除守卫)。

## 0. 三态不变量(裁决 2026-09-24)

**任何客户必须处于且仅处于三种归属之一:在销售名下 / 在公海 / 已删除。**不存在无主又不在池的悬空态(生产已验证 0 违规)。删除是终态,必须留痕:完整快照(客户名/编码/负责人/状态)落系统日志、数据行逻辑删保留,**管理员经 系统管理→系统日志 可查**;且有业务保护——有效开票/回款/在途审批任一存在即拒删(B4)。

## 1. 状态机

```
normal(正常) → warning(临期,≤30天) → expired(到期) → sea(公海池内)
                    ↑ 延期审批通过可回到 active/normal                    ↓ 捞取审批通过 → normal(新负责人)
                                                          archived(归档,不参与统计/提醒/到期检查)
                                                          deleted=1(软删)
```

- 归档与公海客户**不参与**统计、提醒、到期检查(2026-09-22 B5 统一口径)。
- 软删不物理删除,列表按 deleted=0 过滤。
- **客户列表默认页签=「成熟创新」**(裁决 2026-10-09:首屏聚焦在跟客户,与统计卡口径一致;`useCustomerList.js` sanitizeTab 兜底维持 innovate)。
- **「已超期」指标口径=expire_date<今日 且排除公海/归档**,工作台/统计页/列表钻取三处同判据(裁决 2026-10-09,详见 [metrics-definition.md](../metrics-definition.md) §5)。

## 2. 创建与归属

- 创建时客户归属部门自动=负责人部门(`syncCustomerDeptId`);负责人无部门时显式清空,不残留旧部门。
- 集团归属由租户拦截器按 tenant_id 管理,实体无此字段。
- 客户编码自动生成;行业/开发类型走字典(`成熟创新`/`突破开拓`/`铺垫宣传`/`新建改建扩建大修`,最后一项是一个完整分类词,**不可拆分**)。

## 3. 保护期与到期日(唯一公式)

```
到期日 expire_date = 基准日 + customer.protection.days(360) + approved_extend_days(累计已批延期)
基准日 = MAX(最近开票日, 注册日);两者皆空 → 延期时以当天起算
```

- **【生效 2026-10-18·审计 biz-0】开票增删的边界收敛**:新增开票/阶段开票额且**最近开票日前移**
  (新值晚于旧值)时,到期日按新基准重算一次并**清零 `approved_extend_days`**——新保护期已覆盖旧延期,
  不得双重叠加;**补录早于当前最近开票日的旧票不清零、不回退基准、不重算**。逐笔 `addInvoice` 与
  阶段总额 `saveStageAmount` 共用同一私有方法(`advanceLastInvoiceDate`),不再各写一套。
- **作废/删除开票只回算开票推导部分,不收回已批延期**(累计延期独立叠加;2026-09-19 议题一裁决维持)。
- **【裁决 2026-09-24】最近开票日=纯推导字段**(最后一次非作废开票,任何角色不可直改,纠错走发票补录/作废);**注册日**录入后仅 customer:date:edit 持有者(总监 0/行政 05/admin 绑定)可改。
- **【公式修正 2026-10-09 公海死循环复盘】基准日=MAX(最近开票日, 注册日)**——2026-10-08 曾收口为 COALESCE(开票日优先), 开票日早于注册日的 legacy 老票(生产实证 2015/2024 年)把基准拖回过去, 延期审批一通过到期日即变过去日期, 凌晨任务踢回公海(302/303"捞取→掉海→再捞"死循环)。代码两路径(CustomerService.calculateExpireDates 与 ApprovalService 延期执行)均为 MAX, 与 INV-01⭐、finance.md 同口径;本节公式为全系统唯一口径。

## 4. 延期流程

提交 extend 审批 → 审批通过 → `approved_extend_days += customer.extend.days`(默认 360)→ 按唯一公式重算到期日 → 状态回到 active/normal。见 [approval.md](approval.md)。

> **【生效 2026-10-18】延期的生命周期边界**:已批延期只在三种情况下变化——(a) 审批通过累加;
> (b) 新开票/阶段总额使最近开票日**真正前移**时清零(新基准保护期已覆盖旧延期);
> (c) 捞取重置时清零(公海 §6)。补录旧票、作废/删除发票均**不收回**已批延期。

## 5. 每日凌晨检查(2:00,CustomerExpireTask)

逐客户隔离(单条脏数据/唯一键冲突不中断整批,失败记 error 作告警钩子):

| 情形 | 动作 |
| --- | --- |
| 已到期(≤今天) | protection_status=expired、status=expired;**若办事处配置了公海池则入池**(无池配置保持 expired——防 pool_id=NULL 孤儿行,普通用户不可见也捞不了) |
| 30 天内到期(含第 30 天) | protection_status=expiring、status=warning;物化一条 expiring 待办提醒(去重规则见 [reminder.md](reminder.md))。【修复 2026-10-08】任务侧原 `isBefore` 漏掉剩余恰好 30 天的客户(页面/角标/补生成为含边界口径),已对齐为同一窗口 |

## 6. 公海池

- 池按**办事处**配置(matchSeaConfig);同一办事处无配置则不自动入池,手动释放同理。
- **释放**:负责人手动,客户进入所在办事处公海池(可见性按池级权限)。
- **捞取(claim)**:池内 available 状态可申请 → 提交审批 → **原子锁**(条件更新 status available→pending_approval,并发双捞只有一方成功)→ 审批通过 owner 变更为申请人、移出池。
- **【修复 2026-10-08 需求对齐 P1】捞取=新周期重新起算**:登记日重置为捞取日、保护期/调整期天数走 sys_config(`customer.protection.days`/`customer.adjust.days`,原实现硬编码 360/180)、**清零 `approved_extend_days`**(延期是原负责人任内的审批,残留会在下次开票重算时叠加进新保护期,公海回收被架空)、显式置空最近开票日(开票推导基准随新周期重置)。历史发票行不受影响。
- **捞取锁超时释放(裁决 2026-09-24)**:审批锁时长=系统设置 `sea.claim.lock.days`(默认 3 天,0=不启用,管理员可在系统配置页手改);超时由凌晨任务自动释放池行回 available,并同步把对应 claim 审批连同 pending 节点置为 rejected(防释放后补批造成错误过户)。**【体检 H5 修复 2026-10-12】锁定时同步写 `claim_date`(超时判据=lt(claim_date,截止)), 驳回释放同步清空**——此前锁定不写时间戳, NULL 在 SQL 比较中永不命中, 超时释放零触发, 无人审批的锁永久锁死池行。
- **删除**:仅 available 状态且持 `sea:pool:delete`;池编辑(`sea.edit`)不改属主/状态,防池编辑者自领绕过捞取审批。
- **【生效 2026-10-18·审计 data-2】客户列表删除不得留下公海池行**:客户存在 `available` 或
  `pending_approval` 的公海池行时,`CustomerService.delete` 直接拒绝并提示"请先在公海管理删除"。
  公海池行只能由公海管理按池级 `sea:pool:delete` 权限成对删除(客户逻辑删 + 池行物理删),
  不在客户删除路径静默清池行——否则会绕过池级权限,并让审批中的捞取单指向已删客户。

## 7. 转移(2026-09-19 PR-09 上线,09-24 补 fail-fast)

```
PC 客户详情「转移客户」→ 选接收人(候选=当前集团成员,排除现任负责人)
  → 提交 transfer 审批【提交即校验:接收人在册/启用/未删 + 同集团(admin 豁免跨集团)——
     不满足当场报错,不留"已提交却永远无法生效"的单据】
  → 审批人批准 → owner=接收人、客户部门同步=接收人部门、transfer_date=当天
```

- 接收人校验在**提交时与审批执行时双重把关**,口径逐字一致。
- **部门同步含显式清空(【修复 2026-10-08】)**:接收人无部门时客户 dept_id 置空(与创建/编辑 2026-08-12 A3 同口径)——updateById 的 NOT_NULL 策略不写 null,必须显式 set,否则残留旧负责人部门致 ORG 锚点错误关联。
- 小程序端可查看/审批转移类单据,**发起入口仅 PC**。

## 8. 分享

- 即时生效,无需审批;一个客户可分享多人;接收人获得该客户可见性(读)。
- 分享/转移**接收人下拉=当前集团成员**(与数据范围无关,2026-09-23 修正:原按数据范围过滤致跨团队合法转移选不到人)。

## 9. 编辑边界

- 公海池内客户禁止经编辑接口改属主/状态(只能走捞取/释放流程)。
- 非池客户的负责人变更:非 admin 只能走转移审批,直接编辑被拒。
