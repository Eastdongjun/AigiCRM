# AIGICRM 业务不变量清单(INV)

> **版本**: 2026-10-09 · **地位**: 高于一切代码/文档/裁决碎片——任何改动与本清单冲突即视为缺陷,先改清单(须事故复盘或用户裁决背书)再改代码。
> **用法**: ①写代码/改口径前过一遍 A/B 组;②评审 diff 时对照 C 组纪律;③每条不变量标注验证方式,自动钉随门禁跑。
> **变更流程**: 新增/修订须有事故复盘或用户裁决背书,同步补验证钉;删除须用户明示裁决。
> **来源**: 2026-10-09 三案复盘(公海死循环/显示已归档无效/停用断头路)+历史裁决沉淀。

---

## A. 业务数据不变量(违者=数据错乱/用户资产受损)

### INV-01 保护期承诺不可被缩短 ⭐
**表述**: 到期日基准日 = **MAX(最近开票日, 注册日)** + 保护天数 + 累计已批延期。捞取/延期给出的保护期承诺(捞取日+360)**不可被任何后续重算**(延期审批/开票增删改)缩短到过去;新开票晚于注册日照常刷新保护期,老票/补录旧票永远不得把基准拉到建客/最近捞取日之前。
**来源**: 2026-10-09 公海死循环(生产 302/303,legacy 老票把基准拖回 2015/2024,三轮"捞取→延期→凌晨任务踢海")。
**验证**: `CustomerServiceTest.recalc_legacyInvoiceBeforeRegister_keepsExpireAnchoredToRegister` + `ApprovalServiceTest.approve_extend_legacyInvoiceKeepsExpireAnchoredToRegister`(COALESCE 写法即刻红);文档锚点 finance.md §3。

### INV-02 客户三态与终态保护
**表述**: 客户名下(normal/sea)/公海/已删除三态;删除是**终态必须可追溯**(快照留痕)。有业务痕迹(开票/回款/在途审批,**含已作废**)一律拒删,停止跟进走归档。
**来源**: 议题五.3 裁决(2026-09-19)+PR-18。
**验证**: `delete_withInvoices_rejected`(含归档指引断言)/`delete_rejectsWhenActiveApprovalsExist`。

### INV-03 开票日纯推导
**表述**: `last_invoice_date = MAX(全部非作废开票的 invoice_date)`,任何角色(含 admin)不得经客户编辑直改;纠错一律走补录/作废,全程留痕。
**来源**: 2026-09-24 裁决(替换"总监/行政可改"双轨)。
**验证**: `update_rejectsManualLastInvoiceDateChange_evenForAdmin`/作废回算测试。

### INV-04 作废不产生效力但留痕
**表述**: voided 记录不计入统计/保护期/排行/累计金额,但行与原因保留可查,不物理抹除。
**来源**: PR-18 口径。
**验证**: 台账状态机测试群(FinanceTab.spec + 后端 void 系列)。

### INV-05 死提醒零容忍
**表述**: 客户进入终态或转移(删除/入海/捞取/归档/分享撤销)时,其关联 **pending** 提醒必须同批清理——悬挂提醒=列表整列「—」的死数据。processed 历史留痕不动。
**来源**: V2026.09.23.8(expiring 类)+2026-10-09 扩展(分享类,四路径挂钩)。
**验证**: `CustomerServiceTest` 死分享提醒清理 4 钉。

### INV-06 租户 fail-closed
**表述**: 非 admin 用户无集团归属时全部租户表查询**恒空集**(tenant_id=NULL 恒假),不得静默放行或回退默认集团。
**来源**: 租户体系根修(fca0cf78)。
**验证**: 租户矩阵/架构钉。

### INV-07 迁移禁硬编码 id
**表述**: 迁移 SQL 按码/条件定位,零硬编码 id;幂等可重放。
**来源**: 2026-09-23 迁移错删事故(V2026.09.23.1 根修)。
**验证**: 迁移契约脚本群 + MIG 检查。

## B. 交互与文案不变量(违者=用户无路可走)

### INV-10 指引可达性 ⭐
**表述**: 拒绝性提示(报错/拦截)里指引用户去用的功能,**必须真实存在且在该端可达**;跨端指引(小程序说"请在电脑端X")须验证 PC 端确有该入口。
**来源**: 2026-10-09"停用"断头路(文案指向不存在的功能)+MP 无归档入口双断头。
**验证**: `scripts/check-invariants-contract.sh`(自动扫描后端指引文案与跨端指引,随门禁跑)。

### INV-11 术语单一出处
**表述**: 同一功能全系统一个名字(归档≠停用之训)。改功能名必须全链检索旧词:代码+文档+契约脚本+报错文案,一处不净即漂移。
**来源**: 2026-09-19/20 两次裁决用词漂移 + 2026-10-09 契约"财务摘要→开票回款"重钉。
**验证**: 契约脚本群(改名批必须同步重钉,git 归因后改)。

### INV-12 指标口径三处一致
**表述**: 同一指标(如「已超期」)在工作台/统计页/列表钻取与统计卡**同判据同数字**;两页数字不一致=缺陷。
**来源**: 2026-10-09 用户裁决(统一不含公海,实测 0=0=0)。
**验证**: `countExpiredByScope_dateCriteria_excludesSeaArchived` + `page_statusExpired_translatesToDateCriteria`。

## C. 变更纪律不变量(违者=回归事故)

### INV-20 批量替换审例外
**表述**: 机械批量改动(口径统一/重命名/依赖升级/正则替换)**必须逐处 diff 审语义例外**——"统一"恰恰最容易杀死刻意的特例(B5 批 31 处误伤 include_archived 之训)。
**验证**: 人工——批量 PR 必须附逐处清单;评审对照。

### INV-21 边界数据双向验证
**表述**: 公式/口径变更必须用**边界数据正反验证**(最老开票日 × 最新捞取日;空值;0),只验中位数据=没验。
**来源**: 10-08 对齐批只验"两路径同值"未验"老票受害者"。
**验证**: 人工——公式类提交必含边界用例钉。

### INV-22 语义级断言
**表述**: 测试钉"语义正确"而非"规则发生"——断言必须**能区分实现写法**(ne vs notIn/参数含 X 不等于不排除 X);改默认值/公式/口径类提交必含契约钉,防止假绿灯。
**来源**: 三案假绿灯共性(断言过弱,回归后照样绿)。
**验证**: 人工——评审时问"这个断言换个错误写法还会红吗"。

### INV-23 干净态出包
**表述**: 体验版上传/生产部署**必须从干净提交态**进行(或与部署物 md5 对账);工作区中途态禁止出包。
**来源**: 2026-10-09 MP 骨架卡死(上传带了冲刺中途态)+2026-10-06 生产陈旧 jar 事故。
**验证**: 部署脚本 md5 门禁(已有)+人工上传纪律。
