# YCMN 生产部署规范（2026-08-15 磁盘架构迁移后生效）

> 本文件是生产环境的**部署宪法**。所有部署、迁移、备份操作必须符合本规范；
> 部署脚本已内置 `check_deploy_arch()` 自检（每次部署开始自动核对，⚠️ 必须人工确认）。
> 偏离本规范前必须先与负责人确认并更新本文件。

## 1. 磁盘三区架构（用户规划，2026-08-15 迁移落实）

| 区域 | 用途 | 路径 | 禁止 |
|---|---|---|---|
| 系统盘 vda（100G） | **只放操作系统** | / | 放程序、数据库、文件 |
| 数据盘 vdb（400G） | **程序 + 数据库**（路径区分） | /data | 放用户文件 |
| NAS（阿里云 NFS） | **用户文件** | /Aigicrm/files | 放程序、数据库 |

### 数据盘标准布局

| 路径 | 内容 |
|---|---|
| `/data/docker` | Docker 根（镜像 + 容器 + 卷），daemon.json 的 `data-root` |
| `/data/database/mysql-data` | MySQL 数据（**独立于程序路径**，bind 挂载到容器 /var/lib/mysql） |
| `/data/ycmn` | 部署目录（compose/nginx/ssl/部署脚本/jar/日志）；`/root/ycmn` 为指向它的软链接，旧路径引用全部有效 |

### NAS 标准布局

| 路径 | 内容 |
|---|---|
| `/Aigicrm/files/uploads` | 上传文件（后端 bind 挂载 /app/uploads，**线上真实路径**） |
| `/Aigicrm/files/ycmn-dist` | 前端静态资源（nginx 容器挂载） |
| `/Aigicrm/files/backup` | 备份区（daily 每日备份 / dist-rollback / jar 备份） |

## 2. 部署流程（一律走仓库脚本，禁止手工 docker run 偏离标准）

```bash
cd /Users/donglai/东来/01-Projects/01-aigicrm/04-源码/02-迭代源代码/scripts
./deploy-frontend.sh   # 前端: Mac 构建 → NAS dist 切换(自动留回滚副本) → 验证
./deploy-backend.sh    # 后端: 测试服已验证 jar → 生产重建镜像 → 重启 → 验证
./deploy-db.sh         # 数据库: 生产自动备份 → Flyway 迁移 → 结构验证
```

- 每个脚本开始自动执行**部署架构自检**（docker 根 / mysql 挂载 / 软链 / NAS 上传），⚠️ 项必须人工确认后再继续
- 健康检查一律用 `~/.ycmn-deploy.env` 的 `HEALTH_CHECK_USER/PASS`（禁止硬编码密码）
- 部署后必须 `./smoke-test.sh prod` 全绿（PASS=20 FAIL=0）
- 前端源码目录：`04-源码/02-迭代源代码/ycmn-ui`（08-14 仓库重组后的位置）

## 3. 数据库铁律

- **数据必须 bind 挂载 `/data/database/mysql-data`**，禁止用命名卷挂库（防止与程序路径混同）
- 所有 schema 变更走 Flyway：`ycmn-backend/src/main/resources/db/migration/V10+__xxx.sql` + `deploy-db.sh`；不得原地改 V1
- 变更前脚本自动备份（backup-pre-migrate-*.sql），部署前必须有回滚方案
- 应用账号 ycmn_app 无 DDL 权限；迁移仅以 root 经脚本执行

## 4. 文件铁律

- 上传文件只存在于 NAS `/Aigicrm/files/uploads`；旧卷 `upload-data`/`ycmn_upload-data` 是历史回滚副本，**禁止重新挂载**（会"文件消失"）
- 上传文件备份 tar 内含大小写同名文件，**禁止在 Mac（大小写不敏感文件系统）解包**，恢复必须在 Linux 服务器上执行
- 前端 dist 回滚：NAS `backup/dist-rollback-<时间戳>/` 目录内容拷回 `/Aigicrm/files/ycmn-dist/` 即回滚

## 5. 备份规范

- **每日自动**：02:30 cron `/usr/local/bin/ycmn-daily-backup.sh` → NAS `backup/daily/YYYYMMDD/`（保留 14 天）；上传文件备份取 `/Aigicrm/files/uploads`（2026-08-15 修复，旧版指向废弃卷）
- **手动全量**：按 `10-正式环境备份/备份清单.md` 的五类产物（源码/数据库/上传文件/配置/镜像）+ 恢复演练
- 恢复方法见各期 `备份清单.md`；数据库恢复先建库（utf8mb4）再导入，演练在测试服 ycmn-mysql

## 6. 禁止事项（违反即事故）

1. 系统盘放程序/数据库/文件（回滚副本 `/var/lib/docker`、`/root/ycmn.bak-*` 属临时例外，到期删除）
2. 脚本/注释/仓库中硬编码密码、密钥、生产地址
3. 数据库用命名卷（必须 `/data/database/mysql-data` bind）
4. compose up -d 全量执行（mysql 与 backend 的卷行与运行态一致，但历史容器由 docker run 创建，全量 up 会重建容器偏离运行态；仅用 `up -d mysql` 或按脚本部署）
5. Mac 上解包上传文件 tar
