# 需求 A：文件管理页改版（2026-10-16）

> 独立需求，可单独拍板/排期/上线，与其他需求无依赖。
> 来源：客户反馈"文件管理页面没有层次感、看不到完整文件名、按钮太多"。

## 1. 现状问题（代码实证）

- 文件名永远单行截断：`.file-name { white-space:nowrap; text-overflow:ellipsis }`（app.wxss）
- 单行最多 5 个按钮：打开/下载/替换/删除 + 独立的"分享"按钮，把文件名挤到只剩几个字
- "最近文件"恒为标题（不管实际内容）；文件夹是横向小 chips，选中后无路径感 → 没有层次

## 2. 业界参考

Google Drive / iOS 文件 App / 企业微信微盘 / 钉钉云盘的共同做法：

- 一行只有一个首选操作：**整行点击 = 打开**；次级操作收进行尾「⋯」→ 半屏操作面板
- （[NN/g Bottom Sheets](https://www.nngroup.com/articles/bottom-sheet)、[Material Bottom Sheets](https://m1.material.io/components/bottom-sheets.html)、[iOS13 Files 长按菜单](https://www.macstories.net/stories/ios-and-ipados-13-the-macstories-review/6)、[ownCloud 行内⋯菜单讨论](https://github.com/owncloud/android/issues/1396)）
- 文件名最多两行换行，超出才省略；大小/时间/上传人单独一行 meta
- 层次感来自分组：时间分组标题（今天/本周/更早）+ 文件夹大卡与文件小行的尺寸差 + 面包屑

## 3. 设计

```
┌────────────────────────────────┐
│ hero 卡（保留现状） + 搜索框     │
│ tabs：全部/我上传/共享…（带计数）│
├────────────────────────────────┤
│ 📁 全部文件 › 华东区域           │ ← 选中文件夹时显示面包屑
│ ┌──────┐┌──────┐┌──────┐       │
│ │华东 12││华南 8 ││共享 30│ 横滑 │ ← 文件夹大卡（图标+名称+文件数）
│ └──────┘└──────┘└──────┘       │
├────────────────────────────────┤
│ 今天 · 3                        │ ← 时间分组标题（层次感来源）
│ ┌────────────────────────────┐ │
│ │ [PDF] 江苏XX医院照明改造合同… ⋯│ │ ← 文件名最多2行，全名可见
│ │        2.1MB · 今天 14:02 张三│ │ ← meta 独立行
│ └────────────────────────────┘ │
│ 本周 · 5   …                    │
└────────────────────────────────┘
```

- **整行点击 = 打开（预览）**，唯一首选操作
- **「⋯」→ 自绘半屏操作面板**：打开 / 下载 / 分享 / 替换（有权限才显示）/ 删除（红色、置底、二次确认）；全部按现有 showDownload/showReplace/showDelete 权限位显隐，权限逻辑零改动
- **长按行 = 同一面板**（与 ⋯ 等价，兼顾老习惯）
- 文件名 `-webkit-line-clamp:2`；meta 行固定单行
- 列表按 updatedAt 分组：今天 / 本周 / 更早

## 4. 改动范围与工作量

仅 `pages/files/index.{wxml,wxss,js}`（js 增加操作面板状态 + 时间分组视图函数；请求/权限/预览逻辑不动）。

**约 1.5~2 人天。零后端、零 DB、零 PC 改动。**

## 5. 待拍板

1. 操作面板：自绘半屏卡（推荐，带图标、删除标红置底）vs 原生 `wx.showActionSheet`（省事但素）
2. 要不要加"列表/网格"双视图切换（一期建议不做）
3. 长按呼出面板是否需要（建议要，成本很低）
