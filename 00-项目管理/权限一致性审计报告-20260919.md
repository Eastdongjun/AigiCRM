## 二、逐维缺口清单

### A. 后端有但 PC 前端零引用(15 个)——按钮该藏不藏

| 权限码 | 后端保护什么 | PC 前端现状 | 用户体验影响 |
|---|---|---|---|
| **`customer:export`** | 导出 API | 导出按钮无检查 | 无权限者看到按钮→点击→403 报错 |
| **`customer:import`** | 导入 API | 导入按钮无检查 | 同上 |
| **`contact:manage`** | 联系人写(PR-06) | 联系人表单只查 `customer:edit` | 只给 contact:manage 的新角色看不到按钮 |
| **`finance:manage`** | 财务写(PR-06) | 财务表单只查旧组合 | 同上 |
| **`file:upload`** | 上传 API | 文件中心无按钮级检查 | 依赖路由 file:view(能看到=能操作) |
| **`file:edit`** | 替换 API | 同上 | 同上 |
| **`file:delete`** | 删除 API | 同上 | 同上 |
| **`file:share`** | 共享 API | 同上 | 同上 |
| **`file:folder:manage`** | 文件夹管理 | 同上 | 同上 |
| **`file:acl:manage`** | ACL 管理 | AclDialog 移除按钮无检查 | 同上 |
| `task:view` | 任务查看 | 任务页无检查 | 后端兜底,信息暴露风险低 |
| `task:manage` | 任务写 | 同上 | 同上 |
| `incentive:read-stats` | 阅读统计 | PC 不区分 | 低 |
| `ranking:customer:view` | 客户排行 | 路由用 statistics:view 覆盖 | 低 |
| `system:menu:view` | 菜单查看 | 系统 config:view 覆盖 | 低 |

### B. PC 引用但后端 hasAuthority 没有的(4 个)——非真缺陷

| 码 | 解释 |
|---|---|
| `a:add` | 仅存在于测试文件 user.spec.js,非生产代码 |
| `contact:view` | 后端用 `SecurityUtils.hasAuthority("contact:view")`(代码内判断,非注解)——**实际有保护** |
| `customer:date:edit` | 同上(代码内判断) |
| `dashboard:view` | 后端用 `hasAnyAuthority('statistics:view','dashboard:view')`(组合表达式,提取遗漏)——**实际有保护** |

**结论:B 项全部为提取工具的假阳性,实际无缺陷。**

### C. 库中角色绑定了但后端不使用的(6 个)——僵尸绑定

| 码 | 说明 |
|---|---|
| `contact:view` | 后端代码内使用(非注解),实际有效——非僵尸 |
| `customer:date:edit` | 同上 |
| `sea:claim` | 捞取权限——后端用池级权限+sea:claim 兜底,有效 |
| `incentive:manage` | **真僵尸**——后端无此码,绑定无效果 |
| `incentive:read-ranking:view` | 后端有(组合表达式提取遗漏),有效 |
| `incentive:read-stats` | 后端有,有效 |

**真僵尸仅 1 个:`incentive:manage`。**

### D. 后端有但库中没绑定的(5 个)——新码未分配角色

| 码 | 说明 |
|---|---|
| `contact:manage` | PR-06 新增,**未绑定任何角色**(OR 兼容旧码,暂无影响) |
| `finance:manage` | PR-06 新增,同上 |
| `ranking:customer:view` | 未绑定 |
| `task:manage` | PR-10 新增,**未绑定**——任务功能目前仅 admin 可用 |
| `task:view` | 同上 |

**⚠️ 关键发现:`task:view/manage` 未绑定角色意味着除了 admin,没人能用任务功能。需要在系统设置中给销售员/总监角色绑定。**

### E. 字典有但后端没有的(11 个)——字典僵尸

| 码 | 说明 |
|---|---|
| `customer:share` | 后端用 file:share 或 customer:edit,此码已废弃 |
| `incentive:delete` | 后端 updateRecord/deleteRecord 用 incentive:view 底线+方法内守卫 |
| `incentive:manage` | 后端无此码(同 C 项僵尸绑定) |
| `score:ranking` | 后端用 score:view |
| `sea:pool:delete` | 后端无此码 |
| `statistics:scoreboard` | 后端用 score:view |
| `system:menu:edit` | 后端无此码 |
| `system:org:admin` | 后端用代码内判断,非注解 |
| `sea:claim` | 后端用池级权限+此码兜底 |
| `contact:view` | 后端代码内使用 |
| `dashboard:view` | 后端组合表达式使用 |

**真正需要清理的僵尸:`incentive:manage`、`customer:share`、`incentive:delete`、`score:ranking`、`sea:pool:delete`、`statistics:scoreboard`、`system:menu:edit`(7 个)。**

## 三、数据范围审计

### 数据范围覆盖的模块(12 个 Service)

| 模块 | 覆盖方式 |
|---|---|
| 客户列表/详情/导出 | ✅ applyDataScope + OrgScopeResolver |
| 客户排行(原生SQL) | ✅ groupCondition + tenant_id(P0-01 修复) |
| 激励记录/统计 | ✅ visibleUserIds + tenant_id(P0-03 修复) |
| 审批列表 | ✅ applyDataScope(本人申请∨参与∨数据范围) |
| 提醒列表 | ✅ owner 范围 |
| 积分排行 | ✅ visibleUserIds |
| 统计看板 | ✅ countByScope 系列 |
| 公海 | ✅ 池级权限 + 可见池 |
| 系统日志 | ✅ admin 或本人 |
| 用户管理 | ✅ admin 或组织管理员 |
| 文件 | ✅ 文件夹 ACL + scope |
| 联系人/财务 | ✅ 字段级过滤(contact:view/finance:view) |

### 字段级权限规则(库中 5 条)

| 规则 | 效果 |
|---|---|
| 隐藏客户财务数据 | 隐藏 revenue/profit/debt 字段 |
| 隐藏客户联系方式 | 隐藏 mobile/email/address 字段 |
| 禁止导出客户 | action_control: export=false |
| 禁止删除客户 | action_control: delete=false |
| 只读客户 | action_control: create/edit/delete=false |
