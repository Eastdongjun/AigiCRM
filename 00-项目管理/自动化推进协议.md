# AIGICRM 自动化推进协议(autonomous-iteration protocol)

> 本文件是所有自主运行(定时自动化或人工"继续")的唯一执行规程。
> 每轮运行开始必须读本文件;本文件与 `AIGICRM-PR24-todoist.csv`(任务事实源)、
> 中央 `runs/`(证据事实源)共同构成自主推进的三件套。

**版本**:20260919 v1(首轮创建)
**默认参数**:每天 2 轮(09:00/21:00)|权限=全自主不 push|节奏与权限可由用户随时一句话调整

## 1. 每轮固定流程(七步闭环)

1. **定位**:读本协议 + `00-项目管理/AIGICRM-PR24-todoist.csv`,结合 `git log --oneline -5`
   与 runs/ 最近 3 个 run 的 summary,确定"当前做到哪、下一项是什么"。
2. **工程前置**(AGENTS.md 要求):跑 `local_capability_audit.py`;为本轮生成
   `runs/<YYYYMMDD>-<slug>/blueprint.json`(`blueprint_planner.py --project AIGICRM.COM`)。
3. **选件**(规则见 §2)并记录 git 基线(status/diff --check 存 evidence)。
4. **先测后改**:跑该项相关的最小测试(后端单测类/前端 spec/契约)确认基线。
5. **实施**:按该 PR 在 CSV 描述里的验收口径改码;遵守项目代码风格与既有模式。
6. **全量闭环**:后端 `dev-verify.sh backend-test`、前端 `npm run test`+`build`、
   `dev-verify.sh contracts`(须 128+ PASS/0 FAIL)、`sonar analyze secrets`(本轮触达文件)。
   任何红:能定位根因就修(不得吞异常/降断言/关规则);修不动 → **停止,写 handoff**。
7. **收尾**:evidence(命令/退出码/范围/问题数)落 `runs/<run-id>/evidence/summary.md`;
   更新 CSV 该项状态;`git add -A && git commit`(规范消息,含验证摘要)。

## 2. 选件规则

- 顺序:按 CSV 优先级列(P4>P3>P2),同级按 PR 编号;参考《01-统一问题与修改总册》§8 执行顺序。
- **跳过并保持"待决策"**:描述含"业务决策先行/先开会定制度"的项(PR-08/10/14/16 等)——
  自主运行不得代行业务决策。
- **跳过**:已完成项(描述含【已完成】)、无权限项(§3 红线)、依赖未就绪项(在台账注明阻塞原因)。
- 每轮只做一个工作包或其一个子项;做小做透优于做大做粗。
- 环境类验证(需 MySQL/后端)参照 §4;测试夹具必须用后即清、恢复基线计数。

## 3. 硬性红线(任何一轮不得违反)

1. **永不** `git push`/远端操作/开 PR——提交只落本地,由用户审后自行推送。
2. **永不**触碰:生产与测试服务器、`08-备份索引/`、SSH 密钥、真实凭据、阿里云环境目录。
3. **永不**修改已在库中执行过的 Flyway 迁移;新迁移只按命名规范新增。
4. **永不**通过关闭规则/降级断言/删测试/吞异常让门禁变绿。
5. **永不**对业务制度类问题自行拍板(保护期天数、指标口径、审批语义等)。
6. 数据库操作仅限本地 `aigicrm-local-mysql`;自建测试夹具(命名带 PR 前缀)用后精确清除并核对基线计数。
7. 长任务(后端起停/mvn)放后台;每轮结束把本轮起的本地服务停掉(容器可留)。

## 4. 本地活体验证环境规程(需真实后端时)

- MySQL:`docker start aigicrm-local-mysql`(127.0.0.1:3306,口令经
  `docker exec aigicrm-local-mysql printenv MYSQL_ROOT_PASSWORD` 取,不打印到日志)。
- Redis:一次性容器 `aigicrm-local-redis-pub`(127.0.0.1:6380,redis:7-alpine;
  不存在则 `docker run -d --name aigicrm-local-redis-pub -p 127.0.0.1:6380:6379 redis:7-alpine`)。
  宿主 6379 是带认证的共享实例,**禁止触碰**。
- 迁移:先备份(mysqldump 入本轮 evidence),`flyway:repair`(仅标记已删版本)+`flyway:migrate`
  (根=src/main/java/com/aigicrm)。
- 后端:`LOCAL_DOCKER_MODE=1 TENANT_ENABLE=true` + 一次性随机 JWT_SECRET,
  `scripts/start-local-backend.sh` 后台起;用完 pkill spring-boot:run。
- 口令哈希:`htpasswd -bnBC 10 '' '<pass>' | sed 's/^://;s/^\$2y\$/\$2a\$/'`;测试口令仅用随机串。
- 会话集团撤销等租户行为验证必须 `TENANT_ENABLE=true`(本地默认 false 是已知坑)。

## 5. 停止条件(留 handoff,不强推)

- 门禁红了且根因无法在当轮定位/修复;
- 需要业务决策、生产凭据或用户授权才能继续;
- 环境起不来(容器缺失/端口占用)且 5 分钟内无法恢复;
- 发现疑似安全事件(凭据泄露等)——记录并停止,不自行处置。

handoff 写入本轮 evidence/summary.md 的"阻塞"段:现象、已排除的方向、建议下一步。

## 6. 台账口径

- CSV 状态标注格式:`【已完成YYYYMMDD】…(commit xxxx,证据 runs/<run-id>)` /
  `【部分完成YYYYMMDD】…待办…` / `【阻塞YYYYMMDD】原因`。
- "已完成"必须同时具备:代码修改+全量门禁绿+evidence;只满足部分就标部分完成。
- 本协议本身的重要变更:直接改本文件并在版本行追加日期,同时在当轮 summary 记录变更点。
