## 0. 本产品性能三哲学
1. **当前量级小（30 用户/623 客户/496 激励记录），瓶颈不在硬件在代码模式**——实测测试服 CPU 全部 <1%、内存充裕（backend 702M/7.5G）。真正的敌人=**随数据增长的退化**。
2. **已修问题防复发**——MP 卡顿三主因（全量数组拉平/拨盘全量重算/文件页无缓存，2026-10-27 修复）没有性能回归钉，每次改相关代码可能悄悄退化。
3. **测量跟锚点比，不跟感觉比**——锚点见下；测试服云机整体基线偏高（同端点生产公网 configs/public 约 200ms 级），横向对比用同环境数据。

## 1. 接口延迟层（TTFB）
- **怎么测（⚠️ 方法定式 2026-11-11 实证教训）**：**必须带 `-H 'Accept-Encoding: gzip'`**（模拟浏览器）——curl 默认不带压缩头，大响应接口（如检索 352KB）的 time_total 会全是裸传假象（测试服出口仅 22-60KB/s，裸传 6-15s；gzip 后 57KB/1.45s）。且要看**两个数**：`time_starttransfer`（服务端处理）与 `time_total`（含传输），大响应两者差=带宽成本非代码成本。配方=逐端点 1 冷 3 热，P50/P95 排序。
- **首轮基线（2026-11-11 测试服，含测量纠偏后复测）**：
  - **激励检索 keyword（响应 352KB）**：裸 curl 假象 3.2s；**gzip 后 1.45s = 服务端首字节 ~0.9s + 57KB 传输 ~0.5s**。服务端与普通接口同级（sea/configs 首字节 1.24s）；DB 两段实测仅 7.7ms/3.8ms（六路 OR 与 JSON_OVERLAPS 都不慢@496 行）。已做保险性优化（6165cd0e：组装层 600+ 次 DB 往返批量化 + JSON 拆独立查询，**功能 diff 7/7 逐字节等价**）——防数据量增长恶化。**真正可感知改善空间=响应瘦身/服务端分页（涉功能形态，挂账待裁）与带宽**。
  - 🟡 customer/list 分页 P50 1057ms（623 客户量级偏高）。
  - 🟡 scoreboard（JVM 30s 缓存）热 P50 701ms——缓存命中路径仍 700ms+，疑权限解析在缓存外层，待深挖。
  - 🟢 其余 14 端点热 P50 150-750ms。
- **阈值（gzip 口径）**：首字节>1s=🟡挂账；>3s=🔴修复级；gzip 后总耗时>2s 的大响应接口标"响应瘦身候选"。

## 2. 数据库层
- **怎么测**：EXPLAIN 重点 SQL（type=ALL+无 possible_keys=全表扫）；`SHOW VARIABLES LIKE 'slow_query%'`。
- **首轮发现**：
  - 🔴 **slow_query_log=OFF 且 long_query_time=10s——慢查询盲区**：1s-10s 的慢查询（正是激励检索这类）完全不可见。建议开启并设 1s（生产改动走变更纪律）。
  - 六路检索全表扫实证（type=ALL，rows=496，possible_keys=NULL）。
  - 已知索引债：产品路前导 LIKE 走不了 B-tree（结构性，加索引无用，治本=检索架构改造或全文索引）。
- **阈值**：新接口上线前 EXPLAIN 无 type=ALL；核心表行数月度记录（biz_incentive_record 496/biz_customer 623/biz_file ~2500，翻倍即触发检索层评估）。

## 3. 缓存有效性层
- **怎么测**：同接口连续打（30s 窗口内）比冷热差；Δ 大=缓存生效。
- **首轮基线**：permission/list 冷 1580→热 156（Δ1424ms ✅显著）；scoreboard 冷 1090→热 701（Δ389ms ⚠️命中路径仍慢）；多数列表接口 Δ<100ms（无缓存直查，正常）。
- **雷**：30s JVM 缓存类（scoreboard/dashboard/数据范围/文件列表/系统开关）——缓存键含用户维度，勿误判为全局缓存；权限缓存 evict 走写时精确失效（直改 SQL 不 evict，见全景词 §3）。

## 4. 前端加载层（PC）
- **怎么测**：dist 资源体积清单 + 懒加载分包确认（首屏不含大 chunk）。
- **首轮基线**：🟢 健康——xlsx 484KB/docx 168KB/上传组件 164KB **全部懒加载分包不在入口**；入口链 112KB；vue-core 120KB。
- **阈值**：入口链>300KB 或大库进首屏=🟡。

## 5. 小程序运行时层
- **怎么测**：automator 实测（页面切换耗时/setData 体积）；包体积拆析。
- **首轮基线**：包体 724KB（1.0.68）；页面健康（今日 automator 验证过检索/详情/文件页）。**运行时性能本轮未深测**——历史三主因（10-27 修复：打散分组拉平/拨盘局部更新/文件页 30s 缓存/recordId 单组拉取）无回归钉，列入待办。
- **雷**：MP4 先下载后播（2.mp4 实测 8s）——大视频等待感是产品特性限制（无流式），>50MB 视频建议引导压缩。

## 6. 客户端架构隐患层（本产品特有）
- **已确认模式：4 个页面全量拉回+前端 paginate**——incentive/search.vue（卡片墙：86 客户/333 记录全量到浏览器再分页）、case-library.vue、indicator/index.vue、incentive-read-ranking.vue。
- **风险量化**：当前量级可忍（几百条）；客户/记录翻 10 倍=首载 MB 级+浏览器卡顿。**安全上限≈1 万行**，触达前须改服务端分页。
- **怎么测**：`grep -rn "paginate(" src/views/` 扫模式 + 接口响应体积（content-length）监测。

## 7. 容量与资源层
- **怎么测**：`docker stats --no-stream` 采样；压测（k6/ab）只打测试服。
- **首轮基线**：🟢 全空闲——测试服 CPU 均 <1%（backend 0.13%/mysql 0.31%），backend 内存 702M/7.5G。
- **阈值**：CPU 持续>60% 或 backend 内存>3G=容量预警；30 用户量级典型并发（月初排行/报表齐刷 10-20 并发）未压测，列入待办。
