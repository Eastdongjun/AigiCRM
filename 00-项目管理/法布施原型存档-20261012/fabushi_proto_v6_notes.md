## 二、设计说明

### 1. PC/MP 功能一致，只是形态不同
同一套功能（浏览/详情/互动/发布/书目/统计）双端都有：PC 用侧栏+胶囊分类+筛选卡+主从布局+表格；MP 用 feed/卡片/底部 tabBar。PC 员工阅读 5 屏（P1-P5）与 MP 阅读链（A1-A4/B1-B4）一一对应，管理端（P6-P9）继续保留为 PC-only（与 manifest `fabushi.bookManage/contentManage = PC-only` 一致）。

### 2. 菜单口径（第三节实测）
- PC 侧栏七组：首页→业务核心→流程协同→学分管理→**法布施**（分享广场/书目浏览/书目管理/内容治理[角标3]/统计看板）→统计分析→系统管理；页面名取自 `router/index.js` 真实 title，唯「内容流」按 2026-11-16 拍板更名**「分享广场」**（现网代码仍叫内容流，如需同步改代码另行安排——本次任务禁改源码）。
- MP 底栏：首页/四项服务/**法布施**/应用/我的（`app.json` tabBar 实拉），A1=tabBar 页选中态明确；旧 v4 的「文件」tab 已移除。
- C6 应用中心：客户经营→文件管理→四项激励→法布施→学分管理→统计分析→流程协同。

### 3. 权限差异用「一屏一角色」呈现
- P1-P5 = 员工视角（王晓兰 · 销售一部 · 销售员）：法布施组只有 分享广场/书目浏览，无系统管理组；管理三页不出现。
- P6-P9 = admin 视角（张东来 · 系统管理员）：法布施组 5 项全显+内容治理红角标 3；P8 还呈现了长菜单滚动定位后的侧栏（与现网 `scrollIntoView` 行为一致）。
- 所有管理按钮旁/屏注都标了权限码：通过/驳回/停用/挂PDF→`fabushi:book:manage`；下架→`fabushi:content:manage`（必填原因+留痕）；导出→`fabushi:stats:export`（二期）；评论/发布/提交书目→`fabushi:create`。

### 4. 数据口径（只画真实字段，不造假数据）
- 只画后端有的字段：fb_book（书名/作者/版本/页数/状态/pdf）、fb_post（scope_type/正文/时间）、fb_comment、fb_read_status；木鱼=点赞可切换；已读=用户+内容唯一。
- 不画：封面图（书用 CSS 书脊+书名）、点赞人列表、阅读时长、续读率、月目标线数据、假素材（图/音/视一期为文字版）。
- 数字一套贯穿：类别书目数（4/3/3/2/1/2/2/2/5/2=26）、成员榜（王晓兰28/李长青24/周文静19/陈慧15/张东来13）、五联卡（32/58·55%、242篇、木鱼1,847、评论596）、C5 个人四格与 P1 右栏一致。

### 5. 视觉规范执行
- 颜色/圆角/阴影全部收敛 `:root`（PC ~60 个令牌、MP ~50 个），业务 CSS 零硬编码 hex；
- hero-gradient 唯一来源：胶囊 active/侧栏头像/封面书脊；
- 圆角族 16/10/8/999；大数字 tabular-nums；正文 14-15px/1.8；标签 11-12px；
- 图标全部 inline SVG（Element 线性风），全板零 emoji（连 URL 锁、播放三角、木鱼、开关、信号/电池都为 SVG/CSS 绘制）。

### 6. 交互演示点（浏览器打开 HTML 可操作）
PC：P1 胶囊切换过滤+只看未读+重置 · P2 木鱼点击 +1、评论可发 · P3 类别切换过滤 · P4 目录翻页/进度条联动 · P5 弹窗开合/类型胶囊 · P6 通过/驳回行内变状态 · P7 详情弹窗↔下架原因弹窗链路 · P9 周/月切换重排指标。
MP：A1 五页签切换（书架/记录/统计→二期占位面板） · B3 再敲一下重播木鱼动画。
