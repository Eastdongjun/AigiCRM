## 2. 变更纪律（怎么改才是安全的）
1. **序列铁律**：db → backend(md5 必变) → frontend → 冒烟 → 公网标记实证。顺序不可换。
2. **测试服先验**：一切变更先部署测试服、实测通过再上产；backend 走"从测试服提取已验证 jar"（注意：脚本会同步源码到测试服重构建，jar md5 与本地构建不同属正常——**验证方法=同 md5 在测试服行为闭环**）。
3. **回滚锚点三件套先于变更确认**：backend 旧 jar NAS 备份路径、frontend dist-rollback 目录、db flyway 记录——部署输出里必须看到备份回执才算变更开始。
4. **db 迁移**：deploy-db.sh 输出会被 grep|head 截断 Migrating 行，**以 flyway_schema_history 实查为准**；半截失败（MySQL ALTER 非事务）复位配方=删种子行+撤新列+删失败 history 行+还原源行再重跑。
5. **前端部署** = deploy-frontend.sh（构建+暂存校验+备份+入口原子切换+公网验证，失败自动回滚）；测试服无此脚本，走 tar→staging→docker cp 注入（写命令里勿 grep `index-*.js`，Mimosa 会拦；验证拆只读步骤）。
6. **push**：GitHub 直连常超时，走 `git -c http.proxy=http://127.0.0.1:12450 push`；回执以 `git status -sb` 复核。
7. 变更八法检查单（改名/口径/涉数据变更前后逐条执行）：改名先数数/影响面矩阵/完成三级(md5 没变=没部署)/初筛必复核/方向先拍板/不写休眠代码/副本收敛/教训入库。

## 3. 验证标准（怎么证明"真的好了"）
1. **只认 exit code，不认文本**（grep FAIL||echo GREEN 假绿教训：脚本崩溃无 FAIL 字样）。
2. **验证必须到行为层**：UI 改动用浏览器自动化点到最终效果（playwright，NODE_PATH=aigicrm-ui/node_modules，凭据 env 注入）；"按钮能点开"要真点开看到目标元素。commit message 声称修好 ≠ 修好。
3. **换普通角色视角**：admin 视角永远全对——权限类改动必须换普通角色号实测（本项目 t_auto_ty3=销售员/06，行政=t_auto_xz）。"全员可看"档曾因 admin 视角验证而漏掉全线失效。
4. **数据零残留**：测试中改动过的配置/授权，终态与初始逐 id/逐字段核对一致（快照→diff→按 id 还原）。
5. **同 jar 行为闭环**：生产与测试服 md5 相同时，在测试服跑行为闭环=生产实证（jar 构建不可复现，别纠结两次构建 md5 不同）。
6. E2E 残留会造成假失败：先核数据基线再判定（残留状态下的"未收回"可能是脚本没点而不是产品 bug）。
7. 公网实证选对目标：懒加载分包的代码 grep 主 chunk 恒 0（CSS 类在 .css、组件在分包 chunk）——从本地 dist 定位真实 chunk 再 curl。

## 5. 故障响应（出事第一小时）
1. **先定位层级再动手**：入口 4xx/5xx？→ 容器状态 → 后端日志（docker logs 近 200 行）→ 最近一次部署（时间相关性最大）→ db（慢查询/连接数）。
2. **"挂项漂移+服务端干净 = 先疑链路再疑代码"**（冒烟抖动护栏教训）。
3. **回滚优先于修复**（用户可感知故障 >15 分钟）：
   - frontend：dist-rollback-<ts> 目录就位即回滚入口
   - backend：NAS /Aigicrm/files/backup/ycmn-backend-jar-<ts>.jar
   - db：flyway 记录可逆（新迁移 down 或补迁移，永不做无备份 DDL）
   - 回滚后必须冒烟 20/0 + 公网健康双确认
4. **生产故障复现去测试服**：拉同版本 jar/包到测试服复现定位，生产只读观察。
5. 每次故障三问入册：怎么发生的（根因）/ 为什么巡检没抓到（补巡检项）/ 怎么保证不再犯（门禁/契约钉）。

## 6. 本项目专属雷区（实证配方，遇到先查这里）
- **权限矩阵缓存怪癖**：role_perm_scope 直改 SQL 不 evict（restart+relogin 仍旧行为）→ 档位调整必须走权限中心 UI。
- **MyBatis-Plus updateById 默认 NOT_NULL**：字段设 null 被跳过（范围切"全部"/到期改"永久"曾因此不落库）→ 清空式更新必须 LambdaUpdateWrapper 显式 set。
- **Resolver null=全部的语义**：消费端必须写 `== null || contains`；写成 `!= null &&` = 全员档全线失效（5 处曾中招）。
- **Vue ref 漏 .value**：script 区裸用 ref 名调数组方法 → TypeError 静默崩（custs.find 事故）；Set 用方括号索引恒 undefined（thumbFailed 事故）——代码 review 优先抓这两类。
- **功能实现了 ≠ 入口接上了**：detail single 模式死码教训——页面侧支持了参数，跳转没传。改完 grep 调用入口带参。
- **el-dialog 双层叠加**：先关前窗再开后窗；Element Plus 单选按钮 playwright 点击须 force 点原生 input；下拉浮层遮挡后续点击先 Escape。
- **测试服与生产差异**：测试库是生产快照（aigicrm_prod_20261016）；t_auto 行政无办事处中间层（office 档解析空）；admin 密码 ≠ 测试号密码（走 deploy.env 的 HEALTH_CHECK_*）。
- **MP 端**：DevTools 未登录自动化端口拒连；登录须勾协议（automator 用 callMethod('toggleAgreed')，tap 元素不触发）；reLaunch 带 query 到非 tabBar 页会静默重定向；**cli quit 会关用户正在用的 DevTools，勿随手 quit**；automator 点列表行注意表头占 [0]。
- **网络**：生产机自访域名须 --resolve；push 走 12450 代理；py3.14 证书链问题绕行。
- 挂账清单（马吉亮 all 特例/销售员两码/学分排行双端门禁/MP"四项服务"字样/DataScopeGuard/3 真主管 team 行/规则引擎绑定）——动到相关模块先核挂账防翻案。
