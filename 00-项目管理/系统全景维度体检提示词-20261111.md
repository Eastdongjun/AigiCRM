## 3. 权限（本系统最复杂的维度，六层）
1. **功能码**：74 活码（DB 侧 sys_menu 非空 permission 去重 77−2 废弃−1 零绑定=74；代码侧 hasAuthority 字面量去重同为 74，双向闭环）；载体=sys_role_menu+SecurityUtils.hasAuthority（方法级守卫 14 处，**必须和注解一起抓否则误报断链**）
2. **数据范围档位**：UI 配置口径五档（all/region/office/dept/self）；**表实存 7 种**（+custom/team，USER 级组织范围覆写行用），OrgScopeResolver 可解析 10 种 code——查表勿只按五档假设；引擎=OrgScopeResolver（**null=全部**语义，消费端写错=全员档失效，现役修复 4 处注释在案）
3. **角色**：4 个（id1=admin 系统管理员 / id9=05 行政 / id10=0 销售总监 / id11=06 销售员）——role_code 与 id 不是一回事，SQL 取证用 role_code
4. **菜单可见**：用户侧 /api/auth/info menus 按角色过滤（selectMenusByUserId）；管理员端菜单树接口是全量树
5. **文件权限三层**（2026-11-10 终版）：类型(公共/私人/四项激励)→文件夹→文件；组织矩阵底座(file 模块 view=all/manage=dept/delete=self，4 角色逐格实证) + 类型默认矩阵 + 夹级/例外授权(默认永久 expiresAt=null) + 判定链(admin>本人恒管>上级链>授权>矩阵，与 FolderPermissionService.check/checkFile 源码逐行吻合)；建夹门槛=私人全员可建/公共 admin∨FOLDER:create∨组织负责人(最高组织快照)
6. **激励授权**：biz_incentive_grant（canViewShared 默认 1/canViewAll/canEdit/canDelete 默认 0）；**零行默认语义**=无授权行视为"可看分享 true 其余 false"；edit 伞词读时展开为 rename∨replace（ACL 转换兼容）
- **唯一写入口=系统设置→权限中心**（六域：功能与范围/激励授权/公海池/文件权限/生效预览/变更审计；旧角色页 11-03 起只读跳转，UI 层收口——后端 PUT /system/roles/{id} 本身仍收 menuIds）
- **生效时效（分域，勿一概而论）**：功能码/数据范围域=Redis 缓存(perm:ctx:{userId} TTL 10min)+**写时精确 evict+permVersion 版本自愈**（走 UI 改即时生效；直改 SQL 不 evict 即旧口径）；文件授权/激励授权/公海池=表驱动**每请求直查无缓存**；另有系统级开关 30s 缓存（perm.superior.see.subordinate 上级见下属链 / perm.org.leader.see.org 负责人见组织子树，G3 后默认 false）
- 核法：生效预览 GET /system/perm-center/preview?userId=（返回**五块**：user/permissions/scopes/seaPools/incentive，与真实请求同一引擎）；换普通角色号实测 200/403 矩阵
- 雷：updateById 跳 null 字段（范围切"全部"/到期改"永久"须显式 set）；权限变动盯变更审计留痕
