## 一、背景与定位

- **来源**：甲方 20261011 书面需求 + 马总 2026-10-12 口头意见（"没那么复杂：大类→书→上传心得→评论，像四项激励那种"）。
- **定位**：团队阅读与正能量分享社区——围绕书组织内容（在线阅读、诵读、心得），辅以正能量流、互动、统计与自愿提醒。
- **已定裁决（不再讨论）**：
  1. 法布施为**独立模块**：入口在「应用」宫格权限卡（与客户管理平级，第一位），底部 tabBar 保持 首页/四项激励/文件/应用/我的 **零改动**；
  2. **不占用现有文件管理**：自有 `fb_` 数据表与附件命名空间，上传不进文件管理模块列表，配额独立核算；
  3. 视觉沿用系统设计语言（深蓝 #1d4ed8 渐变 + 白卡 + 徽章 chip），参照四项激励模块；
  4. **我方 8 条提升点全部纳入需求**（2026-10-12 用户裁决）：书架+阅读记录、书目审核制、木鱼双用、统计看板升级、统一内容表、电子书续读率指标、成就徽章、NEW+已读未读复用——已分别落到第三节 A2/B3/B4/C4/E1/E3/E5/E6/G4。

## 四、我方提升点（**已全部采纳，2026-10-12 用户裁决**）

以下 8 条已正式纳入第三节需求（对应条目见括号），此处保留立项理由备查：

1. **书架 + 阅读记录**（B3/B4）：甲方没明说，是"微信读书"体验的留存核心——没有它，在线阅读读完即走，没有回访动力。（原型轮已获用户点名采纳）
2. **书目审核制**（A2）：甲方只说"人人可加书名"，直接即显会泛滥；加一道 admin 审核兼顾开放与秩序。
3. **木鱼双用**（C4）：甲方要的是上传成功反馈；把点赞也做成敲木鱼，一个资产两个触点，社区氛围更浓。
4. **统计升级为看板**（E1/E3）：甲方说"如同四项激励"，我方升级为四联指标卡+成员榜+类别热度+每日达成趋势+月目标线，管理层一眼看到价值。
5. **统一内容表**：心得/诵读/正能量共用 fb_post（scope_type 区分），评论共用 fb_comment（type 区分），开发量省约 30%，将来加新内容类型只加枚举。
6. **电子书续读率指标**：验证"进度记忆"是否真被用起来，给二期投入提供数据依据。
7. **成就徽章**（可选）：首次诵读/连续5天/百次木鱼等轻量激励，成本极低。
8. **NEW 徽章 + 已读未读**：沿用四项激励的既有认知，用户零学习成本。

## 六、平台限制（必须让甲方知悉，原型中已如实标注）

1. **PDF 进度记忆**：自建阅读器内翻页可精确记忆（原型所示体验）；若走微信系统打开（openDocument）拿不到页码回调。方案按自建阅读器实现。
2. **提醒推送**：微信订阅消息为一次性授权，**做不到每晚无条件推送**；策略=引导攒授权 + 额度用尽降级应用内提醒。
3. **语音时长**：微信录音组件单段上限 60 秒（需求本意即 60s/段，匹配）。
4. **视频规格**：建议每段 ≤5 分钟、单次 1-5 段（存储与流量控制），超限前端拦截提示。

## 七、验收口径（每块一句话）

- 书目体系：10 类落库；非管理员不能改类别；书目提交后待审核态可见性正确。
- 在线阅读：读到第 N 页退出，重进从第 N 页继续；书架进度同步。
- 三类上传：图/音/视限制前端拦截；上传成功出木鱼；失败有补偿不扣配额。
- 互动：评论/重点/跟读/木鱼计数正确；下架后前端不可见、后台留痕。
- 统计：榜单/热度/趋势数字与底表可对账；导出与页面一致。
- 提醒：当天已读不提醒；授权额度用尽自动降级应用内。
- 工程：权限矩阵 21 用例过；集团隔离 fail-closed；fb_ 配额独立核算。
