#### P0-2 F14/23 延期审批发起仍不校验发起人对客户的归属/查看权限

**证据**（`aigicrm-backend/src/main/java/com/aigicrm/module/approval/service/ApprovalService.java`，`submit()`）：

```
203:  public void submit(String type, Long customerId, String actionAfterApprove, String extraData) {
204:      Long applicantId = SecurityUtils.getCurrentUserId();
206-242  // "claim" 分支：有池级权限 + 可见范围校验 + 原子锁定
244-255  // "extend"/"transfer" 分支：仅「池内客户禁止发起」守卫（sea 状态拦截）
257-286  // "transfer" 分支：接收人有效性 + 集团边界校验
         // ★ "extend" 分支无任何 canAccess / canEdit / 归属 / 查看权限校验
```

**判定**：`extend` 类型提交路径上，除「客户已在公海则拒绝」外，**没有对发起人是否为负责人、是否对该客户有查看权限做任何校验**。与 2026-10-12 测试报告 M1 描述的行为一致，代码侧未见修复痕迹。

**风险**：无查看权限的销售可对他人名下客户发起保护期延期，审批人误批即 `+360 天`（报告同构单据实测 `expire 2027-01-27→2028-01-22`）。

**建议**：在 `submit()` 的 extend 分支复用 `CustomerAccessService.canAccess(customerId)`（与 `transfer` 同型的 fail-fast），并补负例测试钉。
