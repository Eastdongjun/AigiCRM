### 场景矩阵

| 场景 | 后端配置生效？ | 小程序能改名？ | 说明 |
|---|---|---|---|
| 选中某个具体文件夹，该夹 `perms` 含 `rename` | ✅ | ✅ | `resolveFolderPermissions` 读文件夹树 `perms` |
| 上传者本人（公共/私人/分享给我 tab） | ✅（后端本人短路） | ✅ 入口可见 | 但删除/分享的点击处理器仍会拦（见 P1-3） |

| **四项服务 tab** | ❌ | ❌ | 行数据无 `perms`、无 `uploaderId`，页级 perms 硬编码 |

| PC 管理端 | ✅ | ✅ | `FileTable.vue:151-155`、`FolderPanel.vue:24-31` 正常 |

**所以：如果「勾选文件夹权限」指的是选中夹后按夹授权，能改名；如果指根目录 / 类型默认授权（也就是 11-12 两次提交专门做的 `row.perms` 方案），小程序端没生效。**

## 二、阻断级 / 高危缺陷

### P0-1 小程序 `normalizeFile` 丢弃行级 `perms`，T2-MP 修复形同虚设
- `aigicrm-miniprogram/pages/files/index.js:786-807` — `normalizeFile()` 返回的对象**没有 `perms` 字段**。
- `index.js:624-629` — `filteredFiles` 由 `normalizeFile` 产出；`buildFileView` (`:355`) 再用它调 `buildFileRowView`。
- `index.js:278-279` `rowPerms = Array.isArray(item.perms) ? item.perms : null` 恒为 `null`；`actionPerms = rowPerms || folderPerms` 恒走夹级/页级。
- `index.js:469-471` `hasRowPermission()` 同样恒回退 `folderPerms`。
- 影响：管理员在 `FileSpaceDefaults` 勾选「改名/删除/分享/下载」后，`/api/file/list` 返回全量 perms，PC 按钮点亮、服务端放行，**小程序按钮不出现**；这正是用户反复报的「勾了权限看不到」。提交 `afcf9563`（后端 row.perms）与 `42b9ac2e`（MP 行级消费）的意图未落地。
- 修复：`normalizeFile` 透传 `perms: Array.isArray(item.perms) ? item.perms : null`（保留 `null` 以维持「缺失回退夹级」语义）。一行改动，探针已验证有效。

### P0-2 最新提交 `3aaca9d1` 的「四项服务 tab 放开写按钮」实际无效
- 该提交把 `canMutateOwnTab` 改成 `activeTab !== '分享给我'`，并去掉 `shareFile` 的 tab 排除。
- 但四项服务 tab 的数据来自 `buildIncentiveFileRows`（`index.js:38-79`），行对象**既无 `perms` 也无 `uploaderId`**（探针输出确认）；`resolveFolderPermissions` (`:444-445`) 对该 tab 硬编码 `{ perms: ['view','download'] }`。
- 改名门 (`:300`) 需要 `actionPerms.includes('rename') || isOwn`，二者都不成立 → 探针实测 `四项服务 sheet actions: open,download`，写按钮数量为 0。
- 结论：该提交只改了 `showDelete/showShare` 的一个与项，`rename` 门和数据源都没动，宣称的修复没有产生用户可见效果。
- 修复：让 `buildIncentiveFileRows` 从激励记录带上 `uploaderId`/`perms`，或改用 `GET /api/file/list?scope=incentive` 获取后端行级 perms；同时去掉 `:444-445` 的硬编码。

### P1-3 显示层与点击处理器权限口径不一致（本人可见不可点）
- 显示：`index.js:290-300` 用 `actionPerms.includes(x) || isOwn`。
- 处理器：`removeFile:1219` `hasRowPermission(delItem,'delete')`、`shareFile:1329`、`canDownloadItem:474-479` **不含 `isOwn`**。
- 后端 `FolderPermissionService.java:93-94` 明确「上传者本人恒可管理」。
- 后果：本人上传者看到「删除/分享/下载」按钮，点击却弹「没有文件删除权限」；`shareFile` 更是**静默 `return`，无任何提示**。
- 修复：抽单一 `canRowAction(item, action)`（含 `isOwn`），显示层与全部 handler 共用；所有拒绝分支给 toast。

### P1-4 小程序不消费 `folderActions`，夹菜单与 PC 不一致
- 后端 `FileService.java:145,154` 已下发；PC `FolderPanel.vue:24-31` 按 `folderActions?.includes('rename'/'delete')` 显隐。
- MP `flattenFolders` (`index.js:590-596`) 只保留 `id/name/rawName/perms/downloadable`，丢掉 `folderActions`；`openFolderActions` (`:961-976`) 无条件 push 重命名/删除；`openFolderEdit` (`:978`) 零校验；`removeFolder` (`:985`) 只看全局码 `file:folder:manage`；`folder-form/index.js:35` 也只查全局码。
- 后果：给了全局码但未给夹级 rename/delete 的用户，PC 看不到图标，MP 每个夹都能看到 → 提交后 `FileService.java:429/443` 的 `check(P_RENAME/P_DELETE)` 返回 403。
- 更糟：`scripts/check-mobile-file-boundary.sh:223-230` 把「夹菜单只按全局码」钉成了**正向契约**，修复时必须同步改契约，否则 CI 会红。

### P1-5 权限变更后小程序不刷新权限位
- `index.js:508` `initPage()` 只在 `onLoad` 计算一次 `canDelete/canShare/canEditFile/canManageFolder`；`onShow:513-531` 只刷列表数据且有 30s 节流。
- `app.js` 的 `/auth/info` 会更新 `globalData.permissions`，但 tabBar 常驻页面不重算缓存的 `can*` → 管理员改权限后需冷启动/重新登录才生效。
- 修复：`onShow` 在 auth 刷新后重算 `can*`，或改为渲染时直接调 `hasPermission()`。

## 三、改名功能的潜在 bug（后端）

`FileService.renameFile` (`aigicrm-backend/.../file/service/FileService.java:538-570`)

1. **长度校验在拼扩展名之前**（`:547` 判 `name.length() > 200`，`:551` 才 `keepOriginalExtension` 拼回后缀）。`V1__baseline.sql:357` `file_name varchar(200)` → 200 字符主名 + `.pdf` = 204 字符 → MySQL 1406 → HTTP 500。MP `index.js:1249` 同样只校验输入长度。
2. **扩展名被强制小写**：`FileService.java:1304-1308` `extOf()` 用 `toLowerCase(Locale.ROOT)` → `Report.PDF` 改名后变 `Report2.pdf`；`keepOriginalExtension` 对 `a.tar.gz` 只保留最后一段。
3. **无非法字符/重名校验**：`/\ : * ? " < > |`、控制字符、同夹同名都未拦截；上传路径有 `sanitizeFilename` (`:1281`)，改名路径没有。
4. **无事务、无乐观锁**：`selectById → check → updateById` TOCTOU，`BizFile.version` 未使用；`deleteFile` 有事务与受影响行守卫，`renameFile` 没有。并发删除/替换可交错。
5. **文件夹改名更宽松**：`folder-form/index.js:46` 只判非空，后端 `renameFolder` (`:420-434`) 无长度/重名校验，而 `folder_name varchar(100)`（`V1__baseline.sql:389`）→ 超长名 500。
6. `openRenameModal` (`index.js:1237`) 只查全局码 `canEditFile`，`confirmRename` 也不查行级 perms → 与 sheet 门控不一致（服务端仍会拦，属 UX 而非越权）。
