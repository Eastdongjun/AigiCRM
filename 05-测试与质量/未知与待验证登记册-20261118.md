## 8. 数据范围专项核对规范（P0，2026-11-18 用户指令）

> 指令原文：**每一种数据范围都要核对；权限勾选了，被勾选的用户的实际生效数据范围、数据条目，要和数据库比对。**
> 本规范是 A6 / B1 / C1 / C3 的执行细则。

### 8.1 三个「每一个」

| 轴 | 范围 |
|---|---|
| 每一种范围类型 | ALL / ORG（本部门、本组织、含不含子部门）/ OWN / CUSTOM（指定组织、部门、用户集合）/ NONE / 用户级 override / auto_share（superior、admin、roles、users 四开关全组合）/ 组织管理员 / 字段级范围 / 集团（group、legal_entity）隔离 |
| 每一个被授权用户 | 凡在 PermCenter 或角色矩阵中被勾选授予数据权限的用户，**全量逐个核对，不抽样**；含多角色用户、override 用户、组织管理员、停用/离职用户；未勾选用户作为负例（应 fail-closed 返回 0 条） |
| 每一个数据域 | 客户、联系人、阶段金额/开票/回款、公海、审批、文件、激励、积分、统计、提醒、任务、回收站、法布施；凡返回数据条目的接口都算 |

### 8.2 五步核对法（每个用户 × 每个域 × 每种范围）

**Step 0｜勾选动作**：在测试环境 PermCenter / 角色矩阵勾选该权限，记录操作前后配置（谁、何时、勾了什么）。

**Step 1｜落库核对**：读 `sys_perm_grant` / `role_perm_scope`（ROLE 行 + USER 行）/ `perm_scope_org` / `perm_scope_field` / `sys_org_closure` / `sys_org_admin` / `sys_group` / `sys_legal_entity` / `sys_config(customer.auto_share)` / `sys_user.status`，确认勾选已正确落库、无脏值、无孤儿。

**Step 2｜DB 应见集合（expected）**：用**独立 SQL** 从配置表 + 数据归属列（owner_id / dept_id / group_id / legal_entity_id）直接算出该用户在该域应可见的行 ID 集合。
> 铁律：oracle 必须独立于被测代码，禁止复用应用层 `resolveScope` 逻辑——否则解析器有 bug 时两边同错，比对会假绿。

**Step 3｜API 实见集合（actual）**：以该用户 token 调列表、counts-by-filter、详情（IDOR 抽样）、导出、统计聚合、下拉选择器，翻完所有页，收集实际返回行。
- 同一用户同一语义，**列表 / 统计 / 导出 / 选择器必须同集合**（H3 正是这里分裂）；
- 同时比对关键字段值（owner_id、dept_id、group_id、金额、状态）与 DB 是否一致，不只比 ID。

**Step 4｜集合与字段比对**：
- `extra_ids`（实见多于应见）= 越权 → P0 安全缺陷；
- `missing_ids`（实见少于应见）= 权限未生效 → P0 业务缺陷；
- 计数一致：列表 total / 页签计数 / 统计聚合 = 实见集合大小；
- 字段不一致：逐条列出 DB 值 vs API 值。

**Step 5｜生效时机**：权限勾选/取消、角色变更、组织移动、归属转移后立即复测（`perm_epoch` / 缓存即时生效），不允许重登才生效。

### 8.3 判定标准

- 每个用户 × 每个域 × 每种范围：`extra = 0` 且 `missing = 0` 且 `字段差异 = 0` → PASS；
- 任一 `extra > 0` → 阻断级安全缺陷，立即上报；
- 任一 `missing > 0` → 阻断级业务缺陷；
- **组合语义（override vs auto_share vs role custom）未拍板前**：先按单一机制分别核对；组合按候选优先级分别出具差异报告，待 B1 裁决后定稿，不得把「口径未定」写成「通过」。
