# 备份恢复演练 Runbook(体检 P2 第 4 断层清偿方案)

> 背景: 全量体检(2026-10-12)发现强制链四断层之一=「备份从未做恢复演练」——每日备份一直在跑,
> 但从未验证过备份可恢复。本 runbook 落地演练步骤; **生产执行需用户明示授权**(涉及生产机上
> 临时容器/磁盘写入),建议首次演练安排在业务低峰(如周末 20:00 后),全程约 15-20 分钟。

## 演练目标(验收判据)

1. 最新每日备份能完整恢复出全部业务表(表数与生产一致);
2. 关键表行数对账误差为 0(客户/提醒/审批/激励记录);
3. 恢复出的库可被应用账号只读访问(凭据兼容);
4. 演练产物(临时容器/卷)全部清理,生产零残留。

## 步骤(在生产机 SSH 执行)

```bash
# 0) 前置: 确认最新备份文件与大小(每日备份目录, daily 全留)
ls -lh /data/ycmn/backups/ | tail -3          # 以实际备份目录为准(见 backup-retention.sh)

# 1) 起临时恢复容器(不碰生产 ycmn-mysql; 端口 3316 避开)
docker run -d --name restore-drill -e MYSQL_ROOT_PASSWORD=drill-$(date +%s) -p 3316:3306 mysql:8.x
# (镜像版本对齐生产: docker inspect ycmn-mysql --format '{{.Config.Image}}')

# 2) 恢复最新备份(全量 dump)
docker exec -i restore-drill mysql -uroot -p"<drill口令>" < /data/ycmn/backups/<最新dump.sql>

# 3) 对账(在临时容器内; 生产侧行数用 ycmn-mysql 同款查询)
docker exec restore-drill mysql -uroot -p"<drill口令>" -N -e "
  SELECT 'tables', COUNT(*) FROM information_schema.tables WHERE table_schema='ycmn';
  SELECT 'customers', COUNT(*) FROM ycmn.biz_customer WHERE deleted=0;
  SELECT 'reminders', COUNT(*) FROM ycmn.biz_reminder;
  SELECT 'approvals', COUNT(*) FROM ycmn.biz_approval;
  SELECT 'incentive_records', COUNT(*) FROM ycmn.biz_incentive_record;"
# 期望: 与生产同查询逐项相等(备份窗口内无写入时; 演练选低峰即为此)

# 4) 应用账号只读探活(用生产应用账号凭据连 3316 只读 SELECT 1)
#    注意: 演练库含真实数据, 探活后立即清理, 严禁外网暴露(3316 仅本机/内网安全组)

# 5) 清理演练产物(验收后立即)
docker rm -f restore-drill && docker volume prune -f --filter label=com.docker.compose.project=restore-drill
```

## 已知坑(来自历史)

- mysql 临时容器重建若绑定生产网络别名会劫持流量(2026-09-23 事故: network-alias 丢失/误配致 5 分钟中断)
  ——演练容器**不加入**生产 compose 网络,用 -p 3316 端口映射即可;
- 恢复大 dump 用 `pv` 或观察容器日志确认完成再对账(ycmn 库全量约 1-2 分钟);
- root 直跑迁移/恢复不过租户拦截器,属预期(与 deploy-db.sh 同口径)。
