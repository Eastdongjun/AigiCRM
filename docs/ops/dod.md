# 完成定义(DoD — Definition of Done)

> "代码写完"不等于完成。以下全部满足才可宣称功能完成。
> 交付前用 pre-delivery-check.sh 门禁兜底,本文是人工确认清单。

## 功能完成标准(逐项勾选)

### 开发
- [ ] 代码实现完成,无 TODO/占位符
- [ ] 关键逻辑有"为什么"级注释(变量来源/设计原因)
- [ ] 代码已提交 git(commit message 说明改了什么和为什么)

### 需求
- [ ] 需求确认=是(用户已确认需求清单)
- [ ] 需求就绪检查 10 项已勾选
- [ ] 需求变更已回写文档并重新确认(如有)

### 文档(知识资产同步)
- [ ] 涉及数据库 → 重新生成数据字典并提交
- [ ] 涉及权限 → 重新生成权限字典 + 更新权限设计
- [ ] 涉及接口 → 重新生成 API 清单并提交
- [ ] 涉及部署配置 → 更新配置矩阵
- [ ] 涉及业务规则 → 更新 docs/business/

### 测试
- [ ] 冒烟测试通过(smoke-test.sh)
- [ ] 核心回归用例通过(见 smoke-test.sh 回归段)
- [ ] 异常/边界/权限场景已测(按需求中的异常清单)

### 交付
- [ ] 交付门禁通过(verify-delivery.sh)
- [ ] 阶段衔接检查通过(pre-delivery-check.sh)
- [ ] 残余风险已披露(交付报告"已知限制与残余风险")
- [ ] 回滚方案明确(rollback.sh 路径)

## 发布完成标准(发布后)
- [ ] 公网首页/登录 API 200
- [ ] 核心页面人工验证(工作台/客户/激励)
- [ ] 健康日报正常(次日报告无 FAIL)
- [ ] 部署记录写入 deploy.log
